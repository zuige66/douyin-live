# 单项目控制台（2026-10-29）

## 为什么改

以前是「一个后端 + 两个前端」，但网页那个前端有个死循环：

```
网页是桥发的  →  桥没跑就打不开网页  →  想启动桥必须先打开网页  →  卡死
```

所以「启动 / 停止 / 重启」只能长在 DSH 插件面板上（`lib/zhibo.mjs` 里
`spawnDetached` 起进程）。结果是：**离开 DSH 就开不了播。**

现在加了一个 `server.mjs` 当控制台：

```
server.mjs :18082   发网页 + 管桥的启停 + 把其它请求代理给桥
  └── bridge.mjs :18081    业务（登录 / 弹幕 / 回复 / 礼物 / 媒体 / 音乐 / 记忆）
        └── douyin-mcp.exe :18080   由桥自己拉起
  └── native/overlay.py     画面窗口（1920×1080，直播伴侣抓它）
```

关键点：**网页由 server.mjs 发，不再由桥发**。桥死了网页照样能开，
页面上点「开播」就能把桥拉起来。DSH 变成可选项。

## 端口

| 端口 | 谁 | 干什么 |
|------|-----|--------|
| 18082 | `server.mjs` | 控制台网页 + `/ctl/*` 控制接口 + 反向代理 |
| 18081 | `bridge.mjs` | 业务接口（页面里所有 `/dy/*` `/media/*` 都打到这） |
| 18080 | `douyin-mcp.exe` | MCP，桥自己拉起，别手动再起一个 |

换控制台端口：`set ZY_CTL_PORT=18083 && node server.mjs`

## 怎么用

双击 `start.cmd` → 控制台自己打开 `http://127.0.0.1:18082/`。

页面上四个按钮：

- **开播**：起桥（带房间号就连房间，留空就待机）+ 起画面。桥在跑时这个按钮是灰的。
- **重启桥**：停 + 起。**会断开当前监听，直播中别点。**
- **只开画面**：桥在跑、只是画面窗口没了的时候用。
- **全停**：桥（含它拉起的 douyin-mcp）+ 画面窗口一起关。

调试想看桥自己的黑窗口：`start-bridge.cmd`（老脚本，直接起桥，不经过控制台）。

## `/ctl/*` 接口

| 路径 | 方法 | 说明 |
|------|------|------|
| `/ctl/status` | GET | 桥/画面/直播/统计/最近 14 条收发 |
| `/ctl/start` | POST | `{room, mode, demo, withOverlay}` |
| `/ctl/stop` | POST | 全停 |
| `/ctl/restart` | POST | 停 + 起 |
| `/ctl/overlay` | POST | 只开画面 |
| `/ctl/cfg` | POST | `{room, mode, python, chatGap}`，存 `.run/panel.json` |
| `/ctl/log` | GET | `?n=200`，桥日志尾巴 |

## 三个判断口径（都踩过坑）

1. **「桥在不在」只看 `/healthz`**，不看进程。
   进程在但没连房间 = 待机，是另一种状态，页面上要分开显示。

2. **「画面在不在」看桥的 `overlayAgeMs`**，不看 pid。
   画面每 0.4 秒拉一次 `/state.json`，3 秒没拉就是死的。
   只查 pid 会漏掉「手工 `open-overlay.cmd` 起的窗口」和「以前 DSH 起的窗口」
   —— 它们都不在 `.run/pids.json` 里，会被误判成"没开"，然后又 spawn 一个，
   python 那边单实例互斥量秒退，页面上刷一堆假错误。

3. **「停止」不能只杀 pids.json 里的 pid**。
   手工 `start.cmd` 起的桥不在里面。要按端口 `18081` 反查 pid 兜底，
   否则「点了停止没反应」。画面窗口还要按标题补一刀
   （`zuige大肥鱼直播画面` / `大肥鱼直播画面`，taskkill 的 WINDOWTITLE 不支持通配符）。

## 安全

`server.mjs` 只发白名单里的扩展名（`.html/.js/.css/图片/音视频`），
**`.json` / `.txt` / `.py` / `.mjs` 一律 403**。

原因：这个目录里躺着 `llm.json`（API key）、`cookies.txt`（抖音登录态）、
`bridge.mjs`（业务代码）。服务虽然只听 `127.0.0.1`，但浏览器里随手敲一下路径
就能看到，等于把 key 摆在桌面上。点开头的目录（`.run/` `.git/` `.workbuddy-ai/`）
也一并挡掉。

## 跟 DSH 的关系

- DSH 插件（`D:/develop/dsh-douyin-scroll`）**不再需要**才能开播。
- 两个入口别同时用：DSH 那边也会 `spawn` 一个桥，抢 18081 会互相顶。
  想用 DSH 面板就关掉 `server.mjs`，反之亦然。
- DSH 插件里那些 MCP 工具（`douyin_comments` / `douyin_dm` 等）是给 AI 助手用的，
  跟这个控制台是两件事，不受影响。

## 已知问题

- `start.cmd` **必须保持纯 ASCII**。cmd.exe 会把 UTF-8 中文的 `rem` / `echo` 行
  错位解析，然后当成命令执行，报一串 `'xx' is not recognized`。
  中文提示放在网页里。
- 页面里还残留一些「重启 DSH 后才生效」的旧文案（`settings.html`），
  现在重启控制台就够了 —— 那些文案没改，别被带偏。
