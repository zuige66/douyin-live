# 日志页：收发 / 桥日志 / 素材播放

2026-10-29。起因：主人说「控制台里面，把日志跟最近收发都独立出来一个导航栏，
然后加一个视频素材播放的日志」，另外让把截图里那张「音乐」卡理顺。

## 为什么拆

控制台原来一页五块：现在什么情况 / 开播 / 最近收发 / 音乐 / 桥日志。

问题不是长，是**顺序不对**：直播当中最常瞄的是「她刚才到底说没说话」，
可那块排在「开播」那一堆按钮下面，得往下滚才看得见。而收发和桥日志都是
一直往下滚的东西，跟上面的按钮抢眼睛。

拆完控制台只剩两块（状态 + 开播）+ 音乐，一眼一屏。

## 侧栏多一项「日志」

放在**控制台下面**，因为它是直播当中会一直切回来瞄的，不是低频工具。

页面里三个页签：

| 页签 | 数据来源 | 说明 |
|---|---|---|
| 最近收发 | `GET /ctl/status` 的 `recent` | 她说的 + 收到的弹幕（`kind: say/gift`） |
| 桥日志 | `GET /ctl/log?n=N` | `.run/bridge.log` 的尾巴，200/500/1000 行可选 |
| 素材播放 | `GET /media/box` 的 `log` | 哪段视频什么时候播的、谁送的、属于哪一档 |

**素材播放是这次新做的。** 数据本来就有 —— `/media/box` 一直在记
`log: [{ at, line, tone }]`，`tone` 是 `play` / `end`，只是以前没有任何界面读它。
现在按时间轴列出来，配三个数：正在播 / 排队 / 素材总数。
⚠️ 这份留痕存在内存里，**桥一重启就清空**；要长期留档得翻 `bridge.log`。

## 三个实现上的决定

**① 自动刷新只在当前页签跑。** 三个一起轮询没必要，还会把桥的日志接口打爆。
切页签时 `clearInterval` 掉其它的，切回来再开。页面在后台（`document.hidden`）时也不刷。

**② 没变化就不重画。** 收发和素材都是每 2~3 秒拉一次，如果每次都重建整个列表，
正在读的那一行会闪、往上翻的位置会被拽回底部。所以先拼一个 key 比一下，
一样就直接 return；只有内容真变了才重画，而且**只在原本就贴着底部时才自动滚到底**。

**③ 桥日志的「自动刷新」默认关。** 那是纯文本，一次几百行，默认开着会一直跳。
手动「读一次」是主要用法。

## 顺手修的两个真 bug

**① 音乐卡片渲染成一坨（就是主人截图那个）。**
那张卡用的是 `.grid` / `.stat` 两个类名，而这两个类**在这一页根本没有任何样式** ——
上一轮改浅色时我只把别处换成了 `.stats` / `.st`，漏了这张卡。结果四个
「标签 / 值」对变成竖排一行一个，看着像坏了。

改成和「现在什么情况」同一套 `.stats` / `.st`（两列键值，值紧贴标签），
另外把「正在放」单独提出来做成一块（左侧一道绿条），因为它是这卡里唯一有信息量的东西：

```
┌ 正在放  如果呢 · 郑润泽                          2 首 ┐
└──────────────────────────────────────────────────────┘
播放器服务  在跑          播放页  开着
```

顺手给 `.card .sub:empty{display:none}` —— 音乐卡底部的提示平时是空的，
不留一块空白。

**② 日志页的 `media` 页签会把面包屑切成「素材」。**
外壳监听内容区里的 `.tab[data-tab]`，点一下就把左边菜单和地址栏同步过去。
原来的查找条件只看页签名，没看是哪一页：

```js
ITEMS.find((x) => x.page === 'settings' && x.tab === b.dataset.tab)   // 旧
```

日志页有个页签也叫 `media`，正好撞上设置里合并出来的「素材」组 ——
点「素材播放」会把面包屑、左边高亮、多标签页全切成素材，内容却还停在日志。
改成限定当前这页：

```js
ITEMS.find((x) => x.page === view.dataset.page && x.tab === b.dataset.tab)
```

## 深链

`#/logs` 默认最近收发，`#/logs/bridge`、`#/logs/media` 直达对应页签。

外壳的 `route()` 原来只认 NAV 里带的 `tab` 字段（那是给设置页用的），
现在补了一条通用规则：地址第二段就是页签名，任何页都能用。
