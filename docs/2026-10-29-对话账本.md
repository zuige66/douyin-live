# 2026-10-29 对话账本：按天记「谁说了什么、她回了什么」

## 为什么另开文件

原来项目里只有一个 `events.jsonl`，它是**上游原始事件流**：弹幕、礼物、进场、
点赞、房间统计全量往里写，一天 1MB 往上。问题是它**只记进来的，不记她说了什么**。

所以「21:03 那条弹幕她回了没有」这个问题，翻遍日志也答不出来。

`events.jsonl` 不动它 —— 它是排障用的原始证据，混进业务记录只会两个用途都难用。
新的账本单独放在 `logs/`：

```
logs/2026-10-29.jsonl
logs/2026-10-30.jsonl
```

一天一个文件，append-only，一天 100KB 上下。

## 一行长什么样

```json
{"t":1793280367000,"ts":"21:26:07","kind":"chat","user":"森波拉","uid":"3566...","text":"你认识汤令山吗","reply":"认识呀，唱《演员》那个诶","tts":true,"dur":2.4,"parts":1}
```

| 字段 | 说明 |
|---|---|
| `t` | 毫秒时间戳（排障时对齐 events.jsonl 用） |
| `ts` | `HH:MM:SS`，人看的 |
| `kind` | `chat` / `song` / `video` / `gift` / `like` / `chitchat` / `videoIntro` / `videoOutro` |
| `user` / `uid` | 谁。`chitchat` 和视频梗话是空的 |
| `text` | 观众说的原话；视频梗话这里是素材文件名 |
| `reply` | 她说出口的话。**空串 = 这条没回** |
| `tts` | 有没有真出声（false = 只上了字幕） |
| `dur` | 语音时长（秒） |
| `parts` | 拆了几段念（1 或 2，见 C3 改造） |
| `drop` | **没回的原因**。有这个字段就说明这条被丢了 |

`drop` 是这份账本最值钱的地方。以前「观众说了话她没理」是静默发生的，
现在能直接看出是队列满、同句去重、还是生成失败。

## 记什么、不记什么

八个写入点：

| 时机 | kind | 说明 |
|---|---|---|
| 真说出口 | 全部 | `reply` 有值，主记录 |
| 聊天队列满 3 条，挤掉最早那条 | chat | `drop: "聊天队列满 3 条"` |
| 礼物队列满 2 条 | gift | `drop: "礼物队列满 2 条"` —— 送钱的人没被感谢，只有账本能证明 |
| 点歌队列满 6 条 | chat | `drop: "点歌队列满 6 条"` |
| 同人同句 15 秒内重复 | 全部 | `drop: "同句 15 秒内重复"` |
| 视频开场话排太久（> 8 秒） | videoIntro | `drop: "排太久，视频已放一半"` |
| 生成出错 / 没生成出话 | 全部 | `drop` 里带错误摘要 |

**不记**：

- **进场 + 欢迎语**（`kind === 'welcome'`）—— 2026-10-29 主人要求不记。

  > 🔴 第一版理解错了：只挡了上游的 `member` 事件，结果欢迎语走的是正常回复流程，
  > 照样被记进去。实测 10-30 一天 **665 条**，占账本 38%，真正的对话全被淹了。
  > 现在在 `chatLog()` 开头统一 `if (rec.kind === 'welcome') return` ——
  > 八个落点都过这个函数，改一处就够。

- **回放去重**（`isReplay`）—— 那是上游把历史重发一遍，不是新发生的事，
  记进去会把统计搞脏。`stat.dup` 里有计数。
- **没达到阈值的点赞** —— 攒够 8 个才谢一次，剩下的如果也记，
  一个人 5 秒能点 6 下，账本立刻被淹。点赞只记「真谢了的那次」。

## 怎么查

```bash
# 今天开口多少条 / 收到多少条
node -e "const l=require('fs').readFileSync('logs/2026-10-29.jsonl','utf8').trim().split('\n').map(JSON.parse);console.log('开口',l.filter(x=>x.reply).length,'共',l.length);console.log('被丢',l.filter(x=>x.drop).length)"

# 谁来得最勤
node -e "const l=require('fs').readFileSync('logs/2026-10-29.jsonl','utf8').trim().split('\n').map(JSON.parse);const m={};for(const x of l)if(x.user)m[x.user]=(m[x.user]||0)+1;console.log(Object.entries(m).sort((a,b)=>b[1]-a[1]).slice(0,10))"

# 礼物记录
node -e "const l=require('fs').readFileSync('logs/2026-10-29.jsonl','utf8').trim().split('\n').map(JSON.parse);for(const x of l)if(x.kind==='gift')console.log(x.ts,x.user,x.text,'→',x.reply||('【没回】'+x.drop))"

# 哪些弹幕没被回、为什么
node -e "const l=require('fs').readFileSync('logs/2026-10-29.jsonl','utf8').trim().split('\n').map(JSON.parse);for(const x of l)if(x.drop)console.log(x.ts,x.user,x.text,'|',x.drop)"

# 她自言自语说了什么
node -e "const l=require('fs').readFileSync('logs/2026-10-29.jsonl','utf8').trim().split('\n').map(JSON.parse);for(const x of l)if(x.kind==='chitchat')console.log(x.ts,x.reply)"
```

## 实现细节

- **跨零点换文件**按**写入时**的日期判断，不用定时任务。直播到凌晨三点也不会把
  今天的算到昨天去。
- **写失败不影响直播**：`chatLog()` 里所有异常都吞掉，第一次失败时打一行日志
  然后彻底关掉（`logBroken`）。磁盘满 / 权限问题不该让她哑掉。
- **同步写**（`appendFileSync`）：一行 200 字节，每条一次，开销可以忽略。
  换异步反而可能出现「进程崩了最后几条没写进去」。
- `logs/` 已加进 `.gitignore`（运行时产物，不进仓库）。

## 已知边界

- 账本里**没有「她说了但没人听见」以外的情况** —— TTS 失败会记 `tts:false`，
  字幕还在，所以算说过。
- 点赞被节流吞掉的那些**查不到**（见上）。想追这个得改点赞逻辑，不是改日志。
- `song` / `video` 是靠 `ctx.song` / `ctx.video` 有没有值反推的，
  所以「喊了点歌但没点成」也会记成 `song`（`reply` 里能看出来没成）。
- 同一秒内多条会按写入顺序排，没有单调递增的 id，别拿 `t` 当主键去重。
