# 接口与模型（2026-11-02）

主人原话：**「接入 api 好像没有的选择模型」**，随后补充
**「重新接入 api，接入之后，探测有什么模型，然可以选择。然后 dsh 转发跟本地话术就删去吧」**。

## 一、改了什么

**「回复档位」整个概念删掉了。**

以前 `llm.json` 的 `mode` 有三档：

| 档 | 行为 |
|---|---|
| `flash` | 直连 DeepSeek 官方，模型名写死 `deepseek-flash` |
| `dsh` | 跟着 DSH 设置页里选的那个模型走（读 `profiles/*/cordis.patch.yml`） |
| `local` | 不调模型，只用本地话术 |

三档都有问题：

- **选不了具体模型**。`flash` 档的模型名写死在代码里，想换 `deepseek-v4-pro`
  只能去改 `reply.mjs`。主人遇到的正是这个。
- **`dsh` 档大部分情况调不通**。DSH 的 provider 凭证在 DSH 进程里换 token，
  外面没有端口。只有 deepseek 系能打。README 里那张表就是在解释「为什么这档经常不通」——
  一个档需要一张解释表，本身就是设计错了。
- **`local` 当档位是误导**。它不是一种「模式」，是**模型挂了之后的兜底**。
  真选了它，等于主动关掉回复能力。

现在的模型来源只有一个：**`llm.json` 的 `base` / `key` / `model`**。

## 二、面板在哪

`设置 → 账号`（这个页签吃 `account,reply` 两块）→「回复」→ **接口与模型**。

四步：

1. 填**接口地址**（OpenAI 兼容，一般以 `/v1` 结尾）
2. 填 **API Key**（框里留空 = 不改；已存的只显示打码尾巴 `••••2827`）
3. 点**探测模型** → 调 `GET /models`，把列表灌进下拉框
4. 从下拉里挑一个 → 点**保存并测试**

「保存并测试」会真发一句「在吗」过去。**通了才存**（见下面那条铁律）。

## 三、三条设计铁律

### 1. 先试，通了才存

原来的写法是「先落盘再探测」。后果：手滑填错模型名，一点按钮就把**能用的配置
覆盖成错的** —— 直播中那等于当场把她弄哑。

现在 `POST /llm/probe` 的顺序是：

```
probeLLMWith(临时配置)  →  失败：直接返回，磁盘一个字不动
                        →  成功：saveLlmCfg() 落盘
```

`probeLLMWith()` 临时换掉内存里的 `CONF`，试完**无论成败都还原**。泄漏一次，
后面每条弹幕都会走一份没存过的配置，而面板显示的是文件里那份，两边对不上。

实测（错的模型名）：

```json
{"ok":false,
 "why":"HTTP 400：The supported API model names are deepseek-flash, deepseek-v4-pro,
        but you passed no-such-model.（模型名不对？先在面板上探测一下）",
 "saved":false}
```

`llm.json` 完全没变，原来那份还在用。

### 2. key 永远不出桥进程

`GET /llm` 只回打码值：

```json
{"base":"https://api.deepseek.com/v1","model":"deepseek-v4-pro",
 "keyMask":"••••2827","hasKey":true,"env":{"base":false,"key":false,"model":false}}
```

- 面板的 key 输入框**永远回填空**。把打码值塞进 password 框，人会以为框里那把是真的，
  一保存就把真 key 冲成 `••••2827`。
- `POST /llm` 传空 key = 不改。
- `env` 三个布尔是给「环境变量盖住文件」这种情况用的。盖着的时候面板会明说
  「⚠ key 正被环境变量盖住，这里存了也不生效」—— 不然「存了没生效」能查一晚上。

### 3. 模型连不上不能让她哑掉

`route()` 返回 `ok:false` 时，`makeReplyRaw` 直接走 `localReply()`。
所以模型名写错、key 失效、断网，她都还能说话，只是变回关键词话术：

```
$ REPLY_MODEL=no-such-model node reply.mjs 阿伟 "你好呀"
  ⚠ 探不通，用本地话术：HTTP 400：The supported API model names are ...
  大肥鱼：嗨阿伟，我刚还在发呆   (10 字)
```

诊断页的「最近一次失败」会显示原文。

## 四、踩过的坑

### `/llm` 忘了挂白名单 → 全是 404

新路由写进了 `dyRoute()`，但 `bridge.mjs` 里那个**前缀白名单**没加 `/llm`。
表现：设置页「探测模型」点了没反应，浏览器控制台一片 404。

这跟 2026-10-28 的 `/music/` 是**同一个坑**（代码里那条注释就是当时写的）。
两处注释现在互相引用，加新端点记得同步那一行。

### 删了 `mode` 变量，漏了日志里那一行 → 控制台自杀

`server.mjs` 里删掉 `const mode = ...` 之后，519 行的日志还带着 `mode=${mode}`：

```js
log(`桥已起 pid=${spawned.pid} room=${...} mode=${mode}`)   // ReferenceError
```

`node --check` **查不出来**（语法是对的，是运行时的未定义变量）。
实际表现很迷惑：点「一键全开」桥确实起来了，但控制台自己抛异常退出 →
页面报 502 → 状态永远不更新。

**教训：删变量之后要 grep 一遍变量名，不能只靠语法检查。**
已改成报桥自己算出来的那句 `回复=${h.replyMode || '—'}`。

### 探测超时 10 秒太紧

`deepseek-v4-pro` 是推理模型，首字就要 1 秒以上。撞上「桥刚起来自检」和
「面板点探测」同时打接口，10 秒会先到点，报出来还是英文的
`This operation was aborted` —— 看着像接口坏了，其实是超时。

现在 `probeLLM` 用 20 秒（直播时每条弹幕仍走 `llmReply` 自己的 6 秒，那里要快），
超时文案也翻译成「等了 20 秒没回话（接口太慢 / 模型名不对 / 网络卡住）」。

### `HTTP 400` 等于没说

`llmReply` 原来只抛 `HTTP ' + res.status`。模型名错、key 不对、余额空、被限流，
全都长成一句没头没尾的 4xx。现在会捞接口错误体里的 `error.message`，
并按状态码补一句人话：

| 状态 | 补充提示 |
|---|---|
| 400 | （模型名不对？先在面板上探测一下） |
| 401/403 | （key 不对或没权限） |
| 402 | （余额不足） |
| 429 | （限流，等会儿再试） |

## 五、接口清单

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/llm` | 读配置（key 打码）+ 环境变量覆盖情况 |
| POST | `/llm` | 直接存 `{base,key,model}`（不测试） |
| POST | `/llm/models` | 探测模型列表，可带未保存的 `{base,key}` |
| POST | `/llm/probe` | **先试后存**，可带 `{base,key,model}`；返回 `saved` 标记 |
| GET/POST | `/reply/mode` | 已取消。POST 只返回「档位已经取消了」，GET 回当前模型那一句 |

`/reply/mode` 留着是因为 DSH 插件的抖音直播页还在调它。让它收到一句明确的
「已经没有了」，比 404 让那边以为桥挂了强。
