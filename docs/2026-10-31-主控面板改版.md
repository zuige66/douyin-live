# 主控面板改版 · 按 taste-skill 重做（2026-10-31）

## 为什么改

`panel.html` 是主人一天要看好几眼的那一页，但它有三个毛病：

1. **看不出这是「控制台」**。标题是 16px 加一个绿点，和卡片标题一个量级；
   页面里**一个 `h1` 都没有**，也没有一句话说这一场到底好不好。
2. **三张卡片一样重**。`现在什么情况`、`开播`、`音乐` 各占一屏三分之一，
   谁都不是主角 —— 而这一页只有一个真问题：**这场是好的吗，哪一环坏了**。
3. **出事的那一环看不出来**。2026-10-31 晚上正在发生的事：音乐在放、播放页开着、
   面板一片绿，但 **Windows 系统音量是静音的**，观众那边一点声都没有。
   这个事实桥自己算出来了（`/healthz` 的 `music.watch`），面板却没读。

改前用 `inspect.mjs --app` 实测：**2 个 FAIL + 1 个 WARN**
（`no-title` 没有 h1、`emoji` 正文里有 ⚠、`contrast` 「一键全开」白字压
`#18a058` 只有 **3.4:1**）。

## 风格牌

用 `draw.mjs --app` 发牌，命中 **`accent-ladder`**（seed `614898675`，kind `creator`，
screen `overview`）。它的做法是：

> **满色只上小标记，面积全部交给它的浅调。**

正好是这一页需要的：品牌绿只留在状态灯上（浅底 + 深绿字），**一块大色都不上**；
主按钮改成近黑 —— 顺手把 3.4:1 的对比度问题解决了。

`--keep palette,type`：颜色和字体沿用 `ui/theme.css` 的品牌值，只换构图和字号层级。
另外**重画了 shell**：这张牌给的是「带侧边栏的 open plane」，但 `panel.html` 是
`index.html` 外壳里的 iframe，外壳已经有左栏了 —— 照牌再画一道侧边栏就是两个侧边栏。
所以这一页只做画布，不碰导航。

## 这一页的一个问题、一句话发现

**问题**：这场直播是好的吗？哪一环坏了？

**发现**（标题下面那行灰字，按严重程度排，全部来自真实字段）：

| 顺序 | 情况 | 写什么 |
|---|---|---|
| 1 | 桥没跑 | 桥没跑，这一场一条弹幕都收不到。 |
| 2 | 桥待机 | 桥在跑，但还没连上房间：{idleWhy} |
| 3 | **声音出不去** | 房间 X 在播，已经跑了 N 分。**但声音出不去**：系统音量 30%（静音）· 扬声器 … —— 观众听不到。 |
| 4 | 画面死了 | 进程在，但十几秒没来取数据 —— 浮层是死的。 |
| 5 | 都好 | 房间 X 在播，已经跑了 N 分。 |

「没声音」排在「画面死了」**前面**：画面死了看得出来，声音没了看不出来。

## 现在的结构

```
标题行   h1「直播控制台」+ 状态灯 + 一句话发现            [日志 →]
数字条   在线 / 弹幕 / 礼物 / 已回复      一个容器切四格，不是四张卡片
───────────┬──────────────────────────────────────────
主列        │ 侧栏（340）
子系统 ★    │ 音乐   正在放 / 队列 / 播放页 / 出声
 桥/画面/音乐 每行：一条事实 + 一个状态 + 一个按钮
开播        │ 刚刚   最近 5 条：弹幕、答话、礼物
 房间号 / 回复模型 / 一键全开 / 全停
```

★ = 这页最大的块，也是唯一一个「答案 + 动作」合一的地方。

几个刻意的决定：

- **一个按钮，不是一个按钮组。** 以前每行都有「启动 / 重启」两个钮，一个永远是灰的。
  现在没跑写「启动」、在跑写「重启」—— 一个位置只放一个动作。
- **房间号和按钮放在一起。** 点「一键全开」之前能看见要用哪个房间号。
- **「刚刚」搬去侧栏。** 它是「最近发生的」，一列流水；主列留宽度给子系统。
  弹幕数为 0 的时候，靠它判断到底有没有人在说话。
- **「已回复」的旁注写「含入场欢迎」。** 入场、礼物、弹幕都会触发一句回复，
  所以它天然比「弹幕」数大（实测 35 vs 4），不写清楚会让人以为哪里算错了。

## 数据从哪来

以前只读 `/ctl/status`。现在两个接口一起发：

| 接口 | 谁 | 里面有什么 |
|---|---|---|
| `/ctl/status` | `server.mjs` | 桥跑没跑、计数、房间号、回复模式、最近日志 |
| `/healthz` | 桥自己（经 18082 代理） | `music.watch` —— **系统音量、静音只在这里有** |

桥死了 `/healthz` 会失败，这时「出声」显示 `—`，**不冒充「正常」**。
为此改了两条老逻辑：`refresh()` 并发取两个接口；`soundOf()` 拿不到就返回 `null`，
界面显示破折号。**没有改 `server.mjs` 一行代码**，所以不用重启主控、不打断直播。

## 实测结果

`inspect.mjs --app`（1440 / 768 / 390）—— **0 FAIL**，1 WARN：

- `no-data-hue`：这页**没有图表**，全天没有一秒数据系列可以上色。
  强调色按 accent-ladder 的规矩落在三个状态灯上（浅底 + 深字），
  色占比本来就该接近 0 —— 这条我认，不上色是对的。

`lint.mjs --app` —— 0 FAIL，3 WARN（两处 shadow 是浮层和 focus ring，emoji 那条是
中文破折号「——」被误判，都不是问题）。

评审（按 `critique.md` 四项打分，对的是**截图**，不是代码）：

```
ROUND 2（第一轮修完重看）
一秒看懂的：这是个直播控制台，直播中，但声音出不去。
一句话的想法：三个服务排成一行，各自「事实 + 状态 + 一个动作」，
             出事的那个自己变红 —— 不是一排平铺的卡片。
评分：design 7 · usability 8 · creativity 7 · content 8 → overall 7.4
剩下的问题：
1. 三家都在跑的时候「一键全开」是灰的，主按钮消失，第一眼少一个落点。
   （已加 title 说明为什么灰，但没有更好的替代动作 —— 再点一次也是空操作。）
2. 「出声」那条红字带设备名，在 390px 下折成三行，标题行因此变高。
3. 侧栏只有两块，1440 下底部比主列短约 25px —— 在容忍范围内，没有再塞东西凑高度。
```

## 没做的 / 下次可以碰

- **`/healthz` 每 3 秒多一次请求。** 本地、只读、返回几百字节，代价可以忽略；
  但如果以后桥的心跳接口变重，就该改成主控缓存一份塞进 `/ctl/status`。
- **缓存命中率、模型失败数、礼物通道状态**已经从 `/healthz` 拿到了，但没上页面 ——
  它们不是「这一场好不好」的答案，放上去只会多四行数字。
- **面板仍然只能看不能改声音。** 系统静音必须人去 Windows 里调；页面只负责**喊出来**。
