# 2026-10-30 弹幕里「假装送礼」，不许道谢

## 现象

真礼物的感谢是对的 —— 一天 64 条，带昵称、带礼物名，没问题。
问题出在另一批：**观众在弹幕里打字假装送礼，她当真了。**

10-30 一天 29 条，典型样本：

| 时间 | 观众打字 | 她回的 |
|---|---|---|
| 14:57:59 | `送出TOKEN×520` | 折纸大师又来了，这次还带这么大礼 |
| 15:07:45 | `送出一个🚀` | 火箭收到，烟雨你又来啦，谢啦 |
| 15:50:13 | `送出鲜花1000` | 哇，一千朵，我快被花香淹了 |
| 16:33:06 | `送出🌹×66` | LuckDog 又来了，玫瑰我收下啦 |
| 16:42:09 | `送出❤️×99` | 谢谢心心，甜到我了 |

这些的 `kind` 全是 `chat`，**系统一条礼物事件都没收到**。全是嘴上说的。

顺带还暴露出一个附带问题：`送出啤酒*100000000000` 被广告闸门当成
「长数字串」拦下，回了句「群号就不念啦」—— 答非所问。

## 为什么代码没错，她还是被骗了

代码里 `kind === 'gift'` 才走礼物话术，这条 10-27 就修过了，是对的。
问题在**模型那一侧**：

```
userLine 生成的是：「折纸大师ZPl 说：送出TOKEN×520。回他一句。」
```

模型只看到这一句，字面理解就是「他送了我东西」。它**不知道还有礼物通道这回事**，
也不知道「送入」和「送出」在系统里走的是两条完全不同的路。

## 三层修复

### 1. 人设卡（`prompts/dafeiyu-live.md`）

新增一节「礼物这件事，别被骗」，放在「你的梗」之前：

- 真礼物是系统告诉她的，弹幕里打的不算
- 不许说「收到了」「谢谢你的火箭」
- 接法是**软软点破**：「送999个？你倒是真点啊」
- 别生气、别骂人、别说不信任观众的话

改 md 不用重启，热重载，下一条弹幕就生效。

### 2. userLine 逐条提醒（`reply.mjs`）

光靠人设卡会漏 —— 那是 system 里的规则，29 条里保不齐还有三四条上当。
所以在**贴着这句弹幕**的 user 行里再说一遍：

```js
const FAKE_GIFT_RE  = /送出|刷给你|给你刷|送给你(一)?个|送你.{0,4}(礼物|火箭|跑车|鲜花|玫瑰|心心|花束)/
const FAKE_GIFT_NEG = /上次|之前|刚才|昨天|前天|收到没|收到了吗|收了吗|收到没有/
const isFakeGift = (t) => FAKE_GIFT_RE.test(t) && !FAKE_GIFT_NEG.test(t)
```

命中就追加：

```
（注意：他只是在打字，系统一条礼物都没收到。不许说「收到」「谢谢」，软软点破他一句。）
```

**为什么要有 `FAKE_GIFT_NEG`**：有人真送过，再问「我上次送你的礼物收到没」，
那不是假装 —— 点破等于赖账，比道谢还糟。过去式一律不触发。

### 3. 本地兜底（`localReply`）

模型挂着的时候不能让观众看到「刚才还会拆穿，突然又开始道谢」，所以本地
也有一套同方向的台词（「我这儿一条记录都没有，你骗鱼」）。

### 4. 假送礼跳过广告闸门（`makeReplyRaw`）

`送出啤酒*100000000000` 这种会先撞上广告闸门的「长数字串」规则，
回一句「群号就不念啦」—— 假送礼还没轮到点破就被劫走了。

所以标了假送礼的句子**不进入口闸门**：

```js
const fakeHere = ctx?.kind !== 'gift' && isFakeGift(ctx?.text)
const adWhy = fakeHere ? '' : adHit(ctx?.text)
```

出口闸门（`adHit(out)`）照旧兜底，不会真把联系方式念出去。

## 验证

**真礼物照常谢**：

```
kind=gift, 东洋 送出「玫瑰」 → 东洋的玫瑰，收到啦，谢谢
```

**假送礼改成点破**：

```
送出抖音一号×1  → 嘴上送我抖音一号，手倒是没动
送出一个🚀      → 折纸大师，火箭在公屏飞，我这儿空空的诶
送出🌹×66      → 花在公屏上开得挺好，我手里一朵没有诶
```

最后一句值得记一笔：clip 把前半句「折纸大师」砍了、保住了结论。
换个说法就是 —— 如果还是老的截断逻辑，观众会听到「折纸大师，花在公屏上开得挺好」，
**点破没了，变成夸他**。两个改动刚好互相兜住。

**过去式不触发**：

```
我上次送你的礼物收到了吗 → 不点破（走正常兜底）
送给你一首歌            → 不点破（"送给你个"才算）
```

## 没做的

- **纯表情**（`[爱心][爱心][爱心]` → 「爱心收下啦」）没动。68 条里只有少数几条怪，
  大部分表情接得挺好（「[捂脸]三连」「打call我收下了」）。要改再单独说。
- **`[爱心]` 这类表情码算不算礼物**：不算，但它容易误导模型当成爱心礼物。
  暂时观察，真成问题再挡。
- **广告闸门的长数字串**没动。假送礼那条现在走不到闸门，但别的场景
  （比如观众发一串数字）还是会拦。那是另一个话题。
