# 声线可配：设置页换嗓子

2026-10-30。起因是主人问「本地大肥鱼的声线是怎么弄的，能不能在设置里换」。
聊完拍了三件事一起做：**声线进配置**、**语速 + 音高一起放开**、**试听按钮**。
默认声线从晓伊（`zh-CN-XiaoyiNeural`）换成晓晓（`zh-CN-XiaoxiaoNeural`）。

## 一、先说清楚：声线从来不是本地模型

```
bridge.mjs ttsSynth() → tools/tts.py（常驻 --serve）→ edge-tts 云端合成
   → cache/tts/<sha1>.mp3 → tools/play.py（Windows MCI 放音）
   → 本机扬声器 → 直播伴侣采系统声 → 观众听到
```

`edge-tts` 是**调微软在线接口**的壳，不是本地神经网络。所以：

- 能选的嗓子 = 微软免费通道给的那十几个，不是想加就加；
- 断网她就哑，只能出字幕（这条一直没变）；
- 想要「完全另一副嗓子」得换供应商（见 `docs/2026-10-30-开源女声调研.md`）。

## 二、改之前是什么样

两处写死的常量，改一次要重启桥 + tts 常驻进程：

| 位置 | 原来 |
|---|---|
| `bridge.mjs` | `TTS_VOICE = env.REPLY_TTS_VOICE \|\| 'zh-CN-XiaoyiNeural'`；`TTS_RATE = env.REPLY_TTS_RATE \|\| '-8%'` |
| `tools/tts.py` | `DEFAULT_VOICE` / `DEFAULT_RATE`（只有命令行不传参时才用） |

设置页的「声音」只有四个音量滑块，**没有任何音色入口**。

## 三、改了什么

### ① 声线进 `cache/media.json` 的 `tts` 段

```json
"tts": { "voice": "zh-CN-XiaoxiaoNeural", "rate": "-8%", "pitch": "+0Hz" }
```

放这儿而不是单独开 `tts.json`：设置页「声音」那一页改的东西都在这个文件里，
出问题时只看一处。`audio.voice`（音量）和 `tts.voice`（嗓子）名字像，但是两件事。

合成时**现读**，不再有常量：

```js
function ttsCfg() {
  const t = mediaCfg.tts || {}
  return { voice: 校验后 ?, rate: ?, pitch: ? }
}
```

所以保存后**下一句就生效**，桥和 tts 常驻进程都不用重启（常驻进程本来就每条命令
都收 voice/rate/pitch）。这是这次改动最值钱的一点。

环境变量 `REPLY_TTS_VOICE` / `REPLY_TTS_RATE` 降级成「第一次起桥时的初始值」，
不再压着设置页 —— 否则设置里改了没反应，排查起来很绕。

### ② 音高开放（`tools/tts.py`）

`edge-tts` 原生支持 `pitch`，只是以前没接。现在 CLI 和常驻模式都认 `pitch`。

🔴 **缓存 key 兼容**：`key_of()` 里只有 pitch 非默认（非 `+0Hz`）时才把它拼进 sha1。
不这么做的话，加一个功能就把攒了半个月的整库缓存全部作废，直播中前几十句
每句慢 2 秒，观众直接能听出来。

### ③ 设置页：预设 / 手动 / 试听

设置 → 声音 → 声线：

- **预设下拉**：温柔（晓晓原调）/ 甜妹（晓伊）/ 少女（晓伊升调）/ 软糯（晓晓慢柔）/
  东北丫头 / 陕西妹子 / 台湾腔。预设 = voice + 语速 + 音高 的组合，
  手动改任一项会自动跳回「自定义」。
- **音色下拉**：只列**女声**（2026-10-30 主人明确「男生音色不要」），带语种和性格标签。
  桥那边的校验仍是通用正则，手改 `media.json` 填男声也不会崩，只是设置页不再给这个选项。
- **两个滑块**：语速 −30%~+20%、音高 −30Hz~+40Hz。
- **试听一句**：合成一句默认台词，用页面 `<audio>` 放。

### ④ 新接口

| 接口 | 作用 |
|---|---|
| `POST /media/config {tts:{voice,rate,pitch}}` | 保存声线（只收格式对的值） |
| `POST /tts/preview {voice?,rate?,pitch?,text?}` | 合成试听，返回 `{ok,url,dur,cached,ms}` |
| `GET /tts/preview.mp3?n=pv-xxx.mp3` | 直连 `:18081` 时取音频（平时走 `:18082` 静态） |

试听文件落 `cache/tts-preview/pv-<voice>-<rate>-<pitch>-<文本哈希>.mp3`：
换任何一项都是新文件，同组合重复试听直接命中缓存（秒回，不再烧一次接口）。

## 四、两个坑（都是踩过的）

**① 试听不能走 `playFile()`。** 那条路是「直接往本机扬声器放」，设置页控制不了
音量/重放，合成失败时页面也看不出来 —— 主人的感受只是「点了没反应」。
所以改成合成完返回 URL，页面自己放。
⚠️ 但声音终究还是从本机扬声器出来的，**直播中点试听，观众照样听得见**。

**② `/tts/preview` 必须自己写响应。** 它挂在主 HTTP 处理器里（不在 `dyRoute`
白名单内），直接 `return {...}` 没人发结果：页面 25 秒超时，日志里却明明有
「试听合成成功」。第一次实测就是这么挂的，`http=000` 卡满 40 秒。

## 五、实测记录（2026-10-30 18:2x，直播中）

```
18:25:49 语音：zh-CN-XiaoxiaoNeural -8% +0Hz（edge-tts，缓存命中即 0 延迟 · 设置页可改）
18:26:00 🎙 试听 zh-CN-XiaoxiaoNeural -8% +0Hz · 4.7s（合成 1566ms）
POST /tts/preview → 200 · 1.61s · {"ok":true,"dur":3.072,"cached":false,"ms":1604}
GET  /cache/tts-preview/pv-...mp3 → 200 audio/mpeg 18432 bytes
POST /media/config {tts} → ok:true，cache/media.json 已写入

                             preset=warm rate=-8 pitch=0，无 JS 报错
```

热重启用的是 `POST /ctl/restart`（`server.mjs` 那条），桥和画面都正常拉起，
房间自动重连（正在直播时重启是安全的：不是「先起桥后开播」那个假活场景）。

## 六、限制 & 下一步

- 换声线后**旧缓存不复用**（key 含 voice），前几十句每句约 1.6~2 秒冷启动。
  想消掉这段就做「预热」：把常用短句（在呢 / 好听就多听几遍 / 谢谢你的心心）
  用新组合先合成一遍。没做，因为要挑一批台词，得先定清单。
- 可选嗓子就是微软那几个。想真的「换一个人」要么接第三方（花钱、延迟更高），
  要么本地跑开源模型 —— 见 `docs/2026-10-30-开源女声调研.md`。

## 七、2026-10-30 晚补充：只留女声

主人明确「男生音色不要」，设置页的 `TTS_VOICES` 从 10 项砍到 6 项（男声
云希 / 云夏 / 云健 / 云扬 全部撤掉）。

桥那边的校验仍是通用正则 `^[a-z]{2,3}-[A-Z]{2}...Neural$`，**没有**跟着改死 ——
手改 `media.json` 填男声也不会崩，只是界面不再给这个选项。要恢复上下拉里加一行就行。

同时补齐了剩下三副嗓子的试听样音（`cache/tts-preview/6-陕西晓妮.mp3`、
`7-台湾晓臻.mp3`、`8-台湾晓雨.mp3`），至此六个女声全都有对比样音。
