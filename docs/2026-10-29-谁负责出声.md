# 谁负责出声：后台 vs 备用播放页

2026-10-29 傍晚。起因是主人问「是不是漏了这个页面」，指着 18083 上的
`player/player.html`。

## 先说清楚这条链路

```
观众点歌 → 弹幕桥(:18081) → 音乐服务(:18083)  ── 命令队列 ──→  某个网页的 <audio>
                                 取直链 / 记账                      ↑
                                                            必须有一个开着的网页
```

**node 不会出声。** 声音只能由浏览器里一个 `<audio>` 放。所以整条链路的最后
一跳一定落在某个网页上 —— 这个网页就是「出声方」。

## 问题：之前有两个出声方，互相偷命令

| 出声方 | 位置 | 什么时候出现的 |
|---|---|---|
| 后台外壳 | `index.html` 里那个 `<audio>` | 2026-10-29 从 `panel.html` 搬过来 |
| 独立播放页 | `player/player.html`（18083 发） | 更早，替代 DSH 插件时做的 |

两个都每秒 `GET /client/poll`，而这个接口是**取走即清空**：

```js
const cmds = S.commands.splice(0, S.commands.length)   // 谁先来谁拿走
```

后果有两条，都是直播里会真的要命的：

1. **命令被吞**。后台先 poll，把 `play` 拿走了；后台没解锁（浏览器不给声），
   这首歌就静默消失，播放页那边根本没收到。
2. **`unlocked` 被冲成 0**。外壳 poll 时固定带 `unlocked=0`，音乐服务每收到一次
   就把「能出声」标成 false —— 播放页明明在唱，桥那边以为没声。

## 定案：后台出声

选 A（主人拍的）：**直播只开后台一个窗**，播放页降级成备用。

理由：直播本来就得开着后台（开播、看弹幕、切画面都在里面），少一个窗口少一处
「忘了开」。而且 `index.html` 这个文档一直可见，心跳不会断 —— 这正是当初把
`<audio>` 从 `panel.html` 搬进来的原因。

### 改了三处

**① 外壳：没解锁就一次都不 poll**（`index.html` 的 `auTick`）

```js
if (!musicUnlocked) return
```

解锁之前一个字节都不发。这样后台开着不会去偷别人的命令，也不会去冲那个标记。
点过「开启声音」之后才接管。

**② 备用页：默认待机，看得见但不参与**（`player/player.html`）

- 打开只 `GET /state`（只读，无副作用），把正在放什么、队列、音量**显示**出来；
- 看 `state.clientAlive` 判断有没有别人在取命令；
- 有别人在放 → 「接管放音」按钮是灰的，写着「后台正在放音 · 不用接管」；
- 别人没了（后台关了 8 秒以上）→ 按钮才能点，点了才真正开始 poll。

这样「随手打开备用页」不会再把后台的歌偷走。

**③ 侧栏加一个外链入口**：`备用播放页`，`target="_blank"`。

> 🔴 它只能新标签打开，**不能塞进内容区**。内容区是 iframe，一切走就整页卸载，
> 心跳立刻断、声音跟着停 —— 跟当年 `<audio>` 必须住在外壳里是同一个道理。
> 所以它走 `NAV` 里的 `ext` 字段，`ITEMS`（路由表）把它排除掉，点它就是普通外链。

## 为什么不做「自动互斥」

也考虑过让音乐服务记住「谁的解锁占着」，谁的 poll 才发命令。技术上就是给
`/client/poll` 加个 client 标识 + 一个 `owner` 字段，二十行左右。

没做的原因：多一层状态，出问题时**更难判断谁在出声**。而且主人明确说了只开
一个窗，那就不需要在运行时猜。真需要两边都能用时再加，接口留着位置。

## 怎么判断现在是谁在放

```bash
curl 127.0.0.1:18083/state     # clientAlive=true 就说明有页面在取命令
```

在后台 → 顶栏显示「在放 · 歌名」；在备用页 → 按钮灰着。两个都灰/都亮才是异常。
