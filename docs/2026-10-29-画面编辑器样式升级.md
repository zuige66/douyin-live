# 画面编辑器样式升级（2026-10-29）

编辑器从「只能拖位置」升级成「位置 + 颜色 + 常显文字」都能改。老的 `layout.json`
一个字不用动 —— 所有新字段都是**可选**的，不配 = 跟随深/浅主题、用默认字，画面零变化。

## 一、编辑器页面整理

去掉的冗余提示（原话保留在 git 历史里）：

- 「吸附开：自动对齐…/吸附关：随便放」—— 按钮绿色高亮已经表达了状态
- 「读到 N 张图」—— 刷新背景列表成功还弹 toast，下拉列表变长本身就是反馈
- 启动时「读不到画面版式，现在用的是本地草稿」—— 右上角同步胶囊已经亮着，弹两遍
- 「还没有版式文件」「读不到桥，先用本地草稿」「读不到图片列表」「桥没有 /layout/bg」
  —— 全部改成右上角胶囊 + console.log，屏幕上不再重复报
- 「只有点歌台有『上一个卡片』」—— 非 点歌台 时「贴到卡片下面」按钮干脆不渲染
- 右栏空态两行大字压成一行；「背景」「配色」合并成「画布 · 背景与配色」折叠节
  （原生 `<details>`，零 JS）；左栏「想加新组件…」缩成一行

保留的提示（必要反馈）：保存成功/失败、上传图限制与结果、重新载入的 confirm、
弹幕列/显示器抢位置警告、改显示器宽度会重启解码器警告。

## 二、新字段：每组件三个颜色槽 + 常显文字

```
card = 卡片底色    fg = 主文字色    pri = 强调色（高亮/状态点）
颜色一律 #RRGGBB 或 #RRGGBBAA（编辑器的 <input type=color> 出的是 6 位）
```

layout.json 示例（所有字段都可省略）：

```jsonc
{
  "items": {
    "banner":  { "text": "关注大肥鱼不迷路", "pri": "#FFD166" },
    "stats":   { "title": "今天的数据", "live": "LIVE",
                 "labels": ["弹幕", "礼物", "回复"],
                 "card": "#1B3A4B", "fg": "#7FE3FF", "pri": "#FF7AA2" },
    "songs":   { "title": "鱼歌台", "card": "#203018", "fg": "#D8FFA8", "pri": "#FFB347" },
    "monitor": { "idle": "休息一下", "card": "#4A2C3A", "fg": "#FFE9A8" },
    "danmaku": { "fg": "#9BE7C4" },
    "subtitle":{ "card": "#10261BCC", "fg": "#B7F7CD" }
  }
}
```

各槽的实际含义（渲染端落在哪）：

| 组件 | card | fg | pri | 常显文字 |
|---|---|---|---|---|
| banner | — | — | 标语颜色 | `text` 标语（默认「刷礼物有惊喜」） |
| stats | 卡片底 | 标题+数字 | 状态点 | `title`（本场数据）、`live`（直播中）、`labels[3]` |
| songs | 卡片底 | 标题+歌名 | 第一首高亮 | `title`（点歌台） |
| monitor | 外壳色 | 屏幕待机字 | — | `idle`（默认「待机中」，只有没歌没素材时显示） |
| danmaku | — | 弹幕正文 | — | — |
| subtitle | 字幕条底 | 字幕文字 | — | —（字幕内容是 TTS 实时来的，改不了） |
| character | 纯图片，不开放 | | | |

数字（弹幕数/礼物数）、`N 首排队`、歌名、弹幕内容、字幕内容都是**实时数据**，
不在可改之列。stats 的 `labels` 数组允许留空项（空项回落默认），全空 = 整组不用。

## 三、🔴 三处同步

字段名在三个文件里必须一字不差，改任何一处要过一遍另外两处：

1. **editor.html** — `STYLE_SPEC` / `TXT_DEF` 常量（~:316）+ `normalize()`（放行+轻校验）
   + `htmlOf()`（预览渲染）+ `stylePaneHTML()` / `bindProps()`（样式区 UI）。
   预览和真画面读同一份字段；没配的颜色走 `#stage` 的 CSS 主题变量。
2. **bridge.mjs** — `sanitizeLayout()`（~:4923 起）：`STYLE_SPEC` / `LAYOUT_HEX` / `LAYOUT_TXT`。
   颜色正则不对、文字 trim 后为空的直接丢字段（= 回落主题），绝不把坏值送进 render.py。
   文字上限 60 字、标签 20 字、labels 最多 3 项。
3. **native/render.py** — `_hex_rgba()` / `col(comp, slot)` / `stext(comp, key)` /
   `apply_layout()` 里的 `_STYLE` 解析（~:163 起）。
   绘制端所有原来写死 `CARD / INK / PRI / 文案` 的地方改走 `col()` / `stext()`；
   `_STYLE_FALLBACK` 存组件级缺省（显示器外壳/待机字不跟主题，保持原写死值）。
   热更新走原来的 mtime 机制，编辑器保存后 ~1 秒内生效，不用重启画面。

## 四、顺手修的两个预存 bug（跟样式升级无关，但会咬人）

1. **Pillow 9.5 的 `rounded_rectangle` 反矩形崩溃**：当 `2×radius == 短边-2` 时
   内部补角的矩形会画反（y1 < y0）直接 `ValueError`。显示器底座柔影
   `shadow_patch(250, 26, r=12)` 和 `rr_patch(238, 17, r=8)` 正好踩中 ——
   **下次重启画面窗口会首帧崩**。已在 `shadow_patch()` / `rr_patch()` 里把半径
   钳到安全值（`r <= (短边-3)//2`），高斯模糊后看不出差别。
2. **draw_computer 里的局部变量 `col`**（礼物档位色）跟新的 `col()` 取色器撞名，
   改名 `tcol`。

## 五、怎么验证

```bash
# 渲染端离线冒烟（不起窗口、不碰 cache/layout.json，样式 override 全覆盖断言）：
python cache/_style_smoke.py
```

编辑器端：打开 `#/editor` → 点组件 → 样式区改字/取消勾「主题」改色 → 预览即变 →
保存。**注意：桥要用新代码**（重启 start-bridge.cmd），旧桥的 sanitizeLayout
会不认识新字段、存盘时把它们丢掉 —— 编辑器里看起来保存成功，重载后样式丢了，
就是这个原因。
