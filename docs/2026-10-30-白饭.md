# 2026-10-30 白饭：把礼物和 API 钱换成同一个单位

## 为什么要这个

主人要的说法：「收到的礼物」和「我 API 还剩多少钱」，都用**白饭**来讲。
网上很多人这么干 —— 三千块的嘉年华没人有概念，「够吃两年八个月饭」一秒就懂。

## 先纠正一件事：原来的「饭钱」是假的

画面右下角那个「饭钱 0.00」，来自 `cache/money.json`：

- 开局 17.54，**每开口一次固定扣 0.05**，跟真实账单没有任何关系
- 扣到 0 就永远显示 0.00（现在 `left` 就是 0，等于这个数已经死了）

2026-10-27 那么做是有原因的 —— 当时桥里根本拿不到 token 用量，
只能编一个「看着像在花钱」的数字。**现在两个条件都有了**：

1. DeepSeek 有官方余额接口，只读免费：
   `GET https://api.deepseek.com/user/balance` → `total_balance: 14.77`
2. `reply.mjs` 每条回复都拿到了 `usage`（缓存命中/未命中/输出 token）

所以白饭从一开始就是**真账**，不是第二个假数。

## 两个数上画面，一个数只记账

| 账目 | 从哪来 | 怎么算 | 上画面 |
|---|---|---|---|
| 手里还有 | DeepSeek 真实余额 | 60 秒拉一次；两次拉取之间减去本地估算消耗 | ✅ |
| **本场**收入 | 礼物事件 → 音浪 | 抖币 ÷ 20 = 元 = 碗 | ✅ |
| 今天烧掉 | `usage` | (命中×0.2 + 未命中×2 + 输出×3) 元/百万 token | ❌ 只记账 |

**画面只写收入，不写「净赚」，而且报的是「本场」**（23:20 先说别写净赚，23:26 再定成本场）。

两个弯路都记下来，省得再改回去：

- 第一版写「今天 +50.4」——「收的减烧的」，看着像在报利润，数字一大就特别假。
- 第二版写「今天收入 9.8 碗」——「今天」跨零点要换天，跟屏幕上「本场 02:07」对不上，
  而且主播关心的是**这一场**挣了多少。

现在是 `白饭 14.4 碗 · 本场 2.05 碗`：前面是余粮，后面是本场吃进来的。
**跟直播间左上角的音浪同一个范围**，可以一个个数对。

小数目留两位小数（2.05 而不是 2.1）—— 41 音浪 ÷ 20 就是 2.05，圆成 2.1 就看不出换算关系了。

**本场怎么算**：`cache/rice.json` 里的 `sessionAt`。抖音状态从 `ended`/`offline`
变成 `live` 的那一刻（真·重新开播）清零重记；**桥重启不清零**
（重启时 prev 是 `unknown`，走不到那条分支），手动清用 `POST /rice?reset=1`。

`apiYuan`（烧掉多少）**照样记** —— 它验算余额要用（`手里 = 余额 − 上次拉取后烧的`），
只是不进画面。

一碗 = 一元（`ZY_RICE_BOWL` 可改，`/rice?bowl=2` 也行）。

**抖币口径（2026-10-30 22:28 主人定）**：`20 抖币 = 1 块钱 = 一碗饭`。

这不是充值价（充值 1 元给 10 抖币），是**主播到手价** —— 平台抽走一半，
100 抖币的礼物主播只拿 5 块。白饭讲的是「我能吃几碗」，必须按到手算：
按充值价算等于把自己的收入多记一倍（第一版就是 1 抖币 = 0.1 元，全部虚高一倍）。

于是整条链路非常干净：**抖币 ÷ 20 = 元 = 碗**。一个 40 抖币的礼物 = 2 块 = 2 碗。

**音浪就是抖币（1:1）**，这一点是拿直播间那个数校准出来的（见踩坑 6）：
`tools/rice-recount.mjs --from=19:20` 算本场，结果 41，跟直播间左上角显示的 41 一分不差。

**为什么两条腿走路**：只拉余额，两次拉取之间她花了多少看不见，数字一格一格跳；
只本地估，单价一变、缓存命中率一变就越走越偏。拉成功了就用真值把 `apiSince` 清零对齐。

## 说法要分档，不然没人有概念

`bowlsText()`：

| 范围 | 说法 | 例子 |
|---|---|---|
| 不到 0.75 口 | 「半口饭」 | 小心心 1 抖币 = 0.05 元 → 「半口饭」 |
| < 1 碗 | 按「口」算（一碗十口） | 大啤酒 2 抖币 → 「1 口饭」；鲜花 10 抖币 → 「5 口饭」 |
| 1–89 碗 | 报碗数 | 玫瑰 12 个 = 0.6 元 → 「1 碗」；天鹅羽翼 199 抖币 → 「10 碗」 |
| 90–1094 碗 | 够吃几个月（一天 3 碗 → 一月 90 碗） | 跑车 1200 抖币 = 60 元 → 「60 碗」 |
| ≥ 1095 碗 | 够吃几年（一年 1095 碗） | 嘉年华 30000 抖币 = 1500 元 → 「够吃 1.4 年」 |

浮层上只留一位小数（`bowlsShort`），画面里要短：`白饭 14.7 碗 · 今天 -0.3`。
快没饭了（≤1 碗）数字变红。

## 礼物价表：`cache/gift-price.json`

MCP **不给礼物价格**，只给名字和连击数。所以价表得自己维护：

- `prices`：名字 → 抖币。**精确匹配优先，正向包含兜底**（「送出小心心」认得出小心心；
  **反向包含一律不认** —— 那条会把「抖音」算成「抖音一号」，见下面踩坑 3）
- `tierFallback`：认不出名字的礼物（活动礼物、新礼物、MCP 丢名字）按
  `media.json` 里的档位给个代表价 —— 宁可粗，也别算成 0（观众送了钱、账上一分没进，主人对不上账）
- `_estimated`：标了哪几个价是**估的**。公开价格表查得到确定数的才准，其余差几倍正常，
  看抖音后台账单改一行就行
- **改文件不用重启**：每次算钱前 stat 一次 mtime，变了就重载

⚠️ `media.json` 的 `giftMap` 是**媒体档位**，不是价格，别拿去当价格用：
跑车 1200 抖币、抖音一号 10001 抖币、嘉年华 30000 抖币全在 4 档，差 25 倍。

## 她怎么知道自己的账

桥注册一个回调给 `reply.mjs`：

```js
setRiceHint((kind, text) => ...)   // 返回要贴在 user 行尾巴上的一句话
```

- **收礼必给**：`（这一份折合 20 碗；你手里还剩大约 15 碗（白饭，一碗=一块钱）。想提就提一句，不想提就算了。）`
  礼物名从事件文案里反解（`送出「玫瑰」×5`），不为了两个字段改一路函数签名
- **弹幕只在问到的时候给**：命中 `白饭|饭钱|多少钱|余额|还剩|穷|破产|赚|亏|烧钱` 才注入
- **假装送礼不注入**：一边点破「你没送」一边报「我还剩 40 碗」，等于半推半就收了

为什么贴 **user 行**不塞 system：system 是前缀缓存的对象，塞一条每句都变的余额进去，
命中率当场归零（见 `reply.mjs` 里 cacheStat 那段）。贴 user 只多几十个 token。

另外礼物感谢模板多了一个变量 `{rice}`：写 `谢谢{user}的{gift}，{rice}诶` → 「谢谢阿伟的玫瑰，半口饭诶」。
数字由桥算，模型改不了数，比让它自己折算稳。

## 接口

```bash
curl "127.0.0.1:18081/rice"            # 看账（碗 + 元 + token 成本）
curl "127.0.0.1:18081/rice?poll=1"     # 立刻拉一次真余额
curl "127.0.0.1:18081/rice?bowl=2"     # 一碗按 2 元算
curl "127.0.0.1:18081/rice?reset=1"    # 本场收入清零（画面立刻变 0 碗）
curl "127.0.0.1:18081/rice?on=0"       # 关掉（画面退回旧字段，话术里也不提）
```

**故意没有「加法」**：这里的数应该完全来自真余额和真 token，能手加就说明它会说谎。
想改数就去改 API 账户余额，那才是真的。

`/state.json` 多一个 `rice`：

```json
"rice": { "left": 14.4, "inSession": 2.05, "inSessionText": "2 碗", "sessionAt": 1793368000000 }
```

`left` 是**碗**，可能是 `null`（还没拉到余额）—— 画面这时退回读 `money`，不显示假 0。

## 上线踩的两个坑（2026-10-30 21:45 补）

### 1. 画面永远显示「白饭 0.0 碗 · 今天 +0.0」

桥的 `/state.json` 明明带了 `rice`，画面却一直读不到 —— 因为
`native/overlay.py` 的 `OverlayState.update()` 是**白名单**：

```python
for k in ("online", "chat", "gift", ..., "media"):
```

只把列表里有的 key 拷进画面状态，`rice` 不在里面就被静默丢掉，
`render.py` 拿到的 `st["rice"]` 是空的 ⇒ 退回读旧字段 `token`（=0）。

**这个坑最难查的地方是「两边都正常」**：`/rice` 查着好好的、`/state.json` 里也有，
只有画面是 0。表现和「桥没起来」一模一样，但其实是画面那边的事。

⇒ **以后往 `/state.json` 加任何新字段，都要同步改 `overlay.py` 那份白名单。**
（顺便把 `money` 也补进去了。）

### 2. 「今天烧掉」永远是 0 碗

`syncRiceCost()` 每 5 秒把 `costStats()` 的增量记进账本，当时写的是：

```js
rice.apiYuan = r2(rice.apiYuan + delta)   // ❌
```

5 秒的增量只有 0.0002 元，`r2` 四舍五入到「分」⇒ **每次写回 0.00**，
加一百次还是 0。账单那边明明在扣钱，账本纹丝不动 —— 而且因为
`costSeen` 走的是未圆整的值，看不出任何异常。

⇒ 累加一律用全精度（`rice.apiYuan += delta`），**只在显示和落盘时圆整**。
`loadRice()` 读回来时也不再对 `apiYuan` 做 `r2`。

修完实测：`apiYuan` 0.516 → 0.5199（涨了 0.0039，跟 `costStats().yuan` 对得上）。

### 3. 「抖音」被算成「抖音一号」，一晚凭空多出 1000 碗

上线两小时后主人发现账上是 `今天 +1022 碗`。查 `events.jsonl` 找到原因：

```json
{"gift": {"id": "164", "name": "抖音"}, "comboCount": "1"}
```

MCP 报的礼物名就是两个字 **「抖音」**（真有这个礼物，1 抖币），而价格表里没有它，
于是走了「包含匹配」兜底 —— 当时写的是双向包含：

```js
g.includes(k) || k.includes(g)   // ❌ 双向
```

**「抖音一号」包含「抖音」** ⇒ 两份 1 抖币的礼物按 10001 抖币算，一份 1001 碗。

修法两条，缺一不可：

1. 匹配只允许**正向**（礼物名里带表里的名字），单字名字不参与模糊
2. 价格表补上「抖音」本身

改完按 `events.jsonl` 把今天重算：1590 抖币。再按 20 抖币 = 1 元换算 ⇒ **79.5 碗**。

> 教训：**价格表漏一个名字，代价是整晚的账都是错的**，而且看起来完全合理
> （数字大而已）。所以宁可给未知礼物走「档位兜底的低价」，也不要让它咬到一个
> 名字相近的高价礼物。

### 附带：礼物感谢被点名闸门打回

加了「这一份折合 X 碗」之后，模型跑去算账，忘了叫人名 ——
实测「人气票也收到啦，这碗饭我记着呢」，撞上 `reply.mjs` 的
「礼物必须点名」校验（`!out.includes(ctx.user)`），整句被丢、退回本地话术。

所以礼物那条提示词改成：**先说「必须先叫出他的名字」，饭提不提都行**。
饭是锦上添花，点名才是礼物感谢的本体。

> 顺带发现一个**老问题**（跟白饭无关）：那句闸门是精确子串匹配，
> 她喊「咸鱼的心心收到啦」而昵称是「咸鱼翻身」时也会被判「没点名」。
> 42 次里有一部分是这种误杀。要改再单独说 —— 那会把「礼物感谢」的判定口径动到。

### 4. 账翻倍：`events.jsonl` 里每一笔礼物都是两份

主人看到画面写「今天 +78.8」时说不对。查原始事件流发现：

```
22:14:43  小心心  阿东吖  组合1
22:14:46  小心心  阿东吖  组合1   ← 除了时间戳，一个字节都不差
```

203 条礼物事件，实际只有 101 笔 —— **上游把每笔礼物发两遍**（间隔 2~3 秒）。
桥里有 `isReplay()` 去重（`g|uid|礼物名|数量`，TTL 180 秒），所以实时记账是对的；
错在我当时为了「把今天的账算全」，直接拿 `events.jsonl` 累加，于是全部算了两次。

修法：新写 `tools/rice-recount.mjs`，**去重代码直接从 `bridge.mjs` 抽真源码**
（跟 `tools/replay-dedupe-check.mjs` 一个套路），保证跟桥走的是同一套规则，
不是抄一份副本（副本迟早走散，那时候算出来的账才真的没法解释）。

```bash
node tools/rice-recount.mjs            # 只读，看今天对不对
node tools/rice-recount.mjs --write    # 写回 cache/rice.json（要重启桥才生效）
```

它还会顺手打一行「账本跟事件流差多少」，差得离谱就说明中间有人手改过。

### 5. 价表里有几个价填错了

同一天拿公开价格表（2026 版）核了一遍，改掉的：你最好看 199→**2**、
亲吻 199→**99**、墨镜 199→**99**、游艇 6000→**3888**（豪华邮轮才是 6000）、
城堡 10000→**2888**（梦幻城堡）、浪漫马车 1999→**28888**、直升机 3000→**2999**、
「宇宙中心」其实是**宇宙之心** 18888。表里另外补了比心、保时捷、甜蜜送达、加冕王冠等。

**还剩两个查不到真价的**：`天鹅羽翼`、`为你闪耀`（都按 199 抖币估的）。
按 10-30 的账，这两个占了当天收入 **78%** —— 它们错，整晚的账就错。
知道真价就改 `cache/gift-price.json` 里那一行，**不用重启**（每笔礼物算钱前会看文件有没有改）。

### 6. `comboCount` 是**累计数**，不是新增数 —— 账被放大三倍

主人报了个硬指标：直播间左上角「音浪」现在是 **41**。拿它一对账，才发现两处根本性错误。

事件里长这样：

```
00:15:28  人气票  comboCount=1
00:15:29  人气票  comboCount=2
00:15:29  人气票  comboCount=3
00:15:30  人气票  comboCount=4
00:15:30  人气票  comboCount=5
```

这是**同一串 5 连击**，`comboCount` 是「这串到目前为止攒了几个」，不是「这条新来了几个」。
按它逐个相加，5 连击会算成 1+2+3+4+5 = **15 个**。

修法（`riceGift`）：记「这个人这个礼物上次数到几」，只加**差值**；8 秒没动静算新的一串。
顺带把「每笔礼物发两遍」也兜住了 —— 重复事件带的是同一个 count，差值 0，进不来。

### 7. 天鹅羽翼、为你闪耀是**免费礼物**（0 音浪）

这两个名字在公开价格表里查不到，我先按 199 抖币估的。用音浪 41 校准才发现：
把 19:20 之后所有礼物按「连击取最大」加起来 ——

```
小心心 17 + 入团卡 6 + 人气票 2 + 抖音 2 + 大啤酒 4 + 鲜花 10 = 41
```

**正好 41**，而天鹅羽翼 ×2、为你闪耀 ×1 一分都不能算。也就是说它们是
免费礼物 / 任务奖励，**不产生音浪**。价表里已经把这两个改成 `0`（不是「没查到」，是「真的是 0」）。

修完：本场 41 音浪 ✅ 对得上；全天 195 抖币 = **9.75 元 = 9.8 碗**（之前账上写着 51 碗）。

> 🔑 **音浪是唯一权威**。以后再有礼物对不上，先在直播间看一眼音浪，
> 跑 `node tools/rice-recount.mjs --from=<开播时间>` 对一下，差多少就知道价表错了哪一项。
> MCP 本身**不提供**音浪接口（`get_live_info` / 贡献榜 / `live_room_enter` 都翻过了，
> 只有在线人数和点赞）；直播伴侣窗口上能看，但读它要 `start-mate-agent.cmd` 起着才行。

## 没做的 / 要注意

- **余额现在会出现在直播画面上**。这是主人选的（梗要立得住），但等于公开成本结构，
  也可能招来「你好穷我给你刷点」的施舍型弹幕。想收回就 `curl "/rice?on=0"` 或改 render.py 那一行。
- **价表里一半是估的**（见 `_estimated`）。真收到对不上账的礼物，看抖音后台账单改一行。
- **口径是主播到手，不是观众花的钱**。观众充值 1 元 = 10 抖币，主播到手只有一半。
  所以观众刷了 100 元，账本上只有 50 碗 —— 这是有意的，别当成 bug 改回去。
- **面板还没有饭账本卡片**。现在只有浮层 + `/rice` + 她嘴里；要做卡片再说。
- **`/money` 接口没删**，行为不变（还是老的假账），只是不再有人扣它。
