> 目标：让 DSH 的大肥鱼能自己刷视频、做视频、投稿发视频、发评论。
> 结论先行：**不引安卓模拟器、不碰群控、不录直播**，核心栈收敛为
> **Node（DSH 既有）+ Playwright（录网页视频 + 投稿 RPA）+ biliup + ffmpeg**，
> 全部 Windows 原生可跑。写操作（评论/发布/私信）一律默认关 + 确认闸 + 限速 + 白名单。
>
> star 数与活跃度为 2026-10-29 通过 GitHub API 核实。
> **2026-10-30 主人拍板：视频制作走「DS 写网页动画 → 脚本录屏」路线；
> 直播内容不值得录，录直播/切片/Whisper 字幕整条砍掉。**

## 0.5 视频制作路线（2026-10-30 主人拍板：网页视频 + 录屏）

**流程**：DSH 写一个网页动画页（HTML/CSS/JS，每期只改文案和数据）→ 脚本把页面录成视频
→ TTS 配音（复用项目已有的大肥鱼声线）→ ffmpeg 合成音轨（+字幕）→ mp4 成品。

**录屏两种姿势**（都不花 token）：

| 方案 | 做法 | 适用 |
|---|---|---|
| Playwright 原生录屏（**起步用这个**） | Python：`browser.new_context(record_video_dir=…)`，实时录网页，webm→mp4 | 一行配置；不怕遮挡/失焦/DPI；可 headless。时长=动画时长，偶有帧率抖动 |
| 逐帧截图 + ffmpeg（**模板化后升级**） | `page.evaluate` 把动画时钟拨到第 N 帧 → `--screenshot` 出帧序列 → ffmpeg 合成 | 时长精确到帧、永不掉帧、可 60fps；多写十几行 |

**Token 账**：token 只花在「写页面」，跟视频时长/帧数无关——
写一版页面 ≈ 一次普通编程对话（几千~几万 token）；录制/合成/上传 0 token；
每期改文案数据几千 token；质检让 DSH 看 2~4 张关键帧截图（每张 1~2k），
**不要让它逐帧看视频**。对比按秒收费的文生视频模型，边际成本≈0，
最适合栏目化内容（每日播报/知识卡/榜单/整活）：模板定型后每期只喂新数据。

**配音与字幕**：网页视频默认无声——用项目已有 TTS 生成大肥鱼声线的旁白 mp3，
ffmpeg 合进视频；字幕直接用 DSH 写的文案（渲染进网页动画，或 ffmpeg `subtitles` 烧录），
**不需要 Whisper/SmartSub**（那是给「转录直播说话」用的，这条路已砍）。

原「挂直播录屏 → 切片 → Whisper 字幕」路线（DouyinLiveRecorder / StreamCap /
SmartSub / VideoCaptioner / ChopperBot）**整条砍掉**，项目清单保留在下面当参考，
等哪天想做直播切片再翻出来。

## 6. 技术路线风控对比（为什么这么选）

| 路线 | 代表 | 封号风险 |
|---|---|---|
| 安卓 ADB/模拟器 | Douyin-Bot 系 | **最高**：设备指纹+轨迹检测，且项目已老 → 不走 |
| 网页 Cookie + 协议接口 | dsh-douyin-scroll | 只读低风险；写操作风控高，a_bogus 签名随版本变 → 只读用，写走浏览器 |
| 浏览器自动化 RPA | social-auto-upload | 中：模拟真人、登录态真实，当前最主流可行 → **投稿走这条** |
| UIA 控本机 GUI | mate 系（直播伴侣） | 最低：真人级 GUI 操作 → 已有经验，能用的地方继续用 |
| 官方 API | 开放平台 | 无风控，但抖音个人不可得、B站需入驻 → 备案 |

## 7. 推荐组合与下一步（2026-10-30 整合版）

| 能力 | 方案 | 依赖 |
|---|---|---|
| 刷视频 | 已有插件（不动）；可选加网页自动滑扩展 | 无新增 |
| **做视频** | DSH 写网页动画（模板化）→ Playwright 录屏（起步）/逐帧+ffmpeg（进阶）→ 项目已有 TTS 配音 → ffmpeg 合成 | Playwright（Python）+ ffmpeg |
| 发视频 | B站 → biliup；抖音 → social-auto-upload（浏览器 RPA + 定时发布） | Rust/Python |
| 发评论 | 已有插件开闸 + 限速 + 白名单（只回自己直播间/视频） | 无新增 |

**落地形态（主人 2026-10-29 拍板）：独立工具 + API。**
做一个本地 HTTP 服务（如 `zhibo-auto`，挂进 18082 控制台体系，端口 1808x）：

```
POST /video/make         视频任务：{模板, 文案/数据, 配音文本} → DSH 写页 → 录屏 → TTS → 合成 mp4
POST /video/preview      只出 3~5 张关键帧截图给 DSH/人看效果，不录全片
POST /publish            投稿（平台、视频、标题、简介、定时；默认 dry-run）
POST /comment            评论（白名单+限速；默认 dry-run）
GET  /jobs               任务队列与结果（审计日志）
```

注意分工：**写页面是 DSH 的活**（它本来就是干这个的，`/video/make` 收到任务后
把「模板+文案」交给 DSH 会话产出页面文件，服务只负责录屏/配音/合成这些机械步骤）；
服务自己不产内容、不花 token，token 只在 DSH 写页面和看预览时花。

特点：DSH、控制台面板、任何 agent **只要会调 HTTP 就能用**，不绑死 DSH；
所有写操作先出草稿（dry-run）再由人（或 DSH 的 confirm 闸）放行；
队列串行 + 全量留痕，单账号、低频、可审计。

**建议开工顺序**：① 录屏脚本（Playwright 起步）+ 一个手动喂页面的最小闭环 →
② 接 TTS/ffmpeg 合成 → ③ B站 biliup 投稿 dry-run → ④ 抖音 social-auto-upload →
⑤ 评论开闸策略。每条单独提交，跑稳一条再开下一条。

## 风险红线（自用也必须守）

- 单账号、低频、夜间不跑写操作；评论/私信/发布默认关，每道都要确认
- 白名单：评论只回自己直播间/自己视频下；投稿内容必须过人工审
- Cookie 只存本机（沿用 dsh-douyin-scroll 的约定），不进仓库不上传
- 坚决不用群控/云控/多开营销类工具；不碰协议刷量（人气/粉丝/点赞）
