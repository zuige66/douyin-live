# 开源女声调研：除了微软那几个，还能用谁的嗓子

2026-10-30。主人问「帮我找找网上其他开源的声线，女声」。这篇是选型材料，
**没有动代码**（要不要接、接哪个，等拍板）。

## 一、先看这台机器的天花板

```
CPU: Intel Core Ultra 5 225H（14 核 14 线程，核显 Arc）
GPU: 无 NVIDIA 独显（nvidia-smi 不可用）
```

这条决定了大半结论：**所有「声音克隆」类大模型都出局**。
它们的官方速度都是 4060Ti / 4090 口径，纯 CPU 上 RTF 会掉到 3~10 倍实时
（一句 3 秒的话要等十几秒），直播间根本没法用。

能在无独显机器上跑进实时的，只有 82M~15M 参数量级的小模型。

## 二、现成女声（下载即用，不用自己录音）

| 项目 | 许可 | 中文女声 | 要不要 GPU | CPU 表现 | 备注 |
|---|---|---|---|---|---|
| **Kokoro-82M v1.1-zh** | Apache-2.0 | **约 50 个**（`zf_001` 起），另有 50 个男声 | 不要 | M1 Pro 纯 CPU 实测 RTF 0.88（10 秒长句约 9 秒）；首包 <100ms（流式） | **目前最值得试的一条**。100 个音色由龙猫数据授权，官方管线要 `misaki[zh]`；第三方 ONNX 客户端会吞声调符号，念出来像外星人 |
| **Kokoro-82M v1.0** | Apache-2.0 | 4 个（`zf_xiaobei/xiaoni/xiaoxiao/xiaoyi`） | 不要 | 中文 100 字 → 21.9s 音频，生成 8.3s（RTF≈0.38） | 就是现在 edge 那四副嗓子的蒸馏版，听感接近 |
| **MeloTTS** | MIT | `ZH`（内置就一个女声） | 不要 | CPU 实时 | 中英混读强、装起来最省事；音色单一，韵律一般 |
| **Piper** `zh_CN-huayan-medium` | 引擎 GPL / 音源许可 Unknown | 华言（女） | 不要 | 0.39s，离线 | **已经在仓库里**（`tools/piper-voices/`，63MB）。当初就是因为音色太平才换掉 edge |
| **CosyVoice3-0.5B** | Apache-2.0 | 预置 `longcheng`（中文女）+ 方言女声（四川幺妹/上海阿宝） | 要 | CPU 太慢 | demo 参考音固化成命名说话人，不用每次上传音频 |
| **CosyVoice-300M-SFT** | Apache-2.0 | 7 个预置音色，中文女 `zh-CN-001 小雅` | 要（CPU 约 4.3s/句） | 勉强 | 音色少而稳，适合当「标准播音女声」 |

| **Fish-Speech** | Research License（**非商用**） | 预置 `default_female` | 要 | — | 1.7B，音质好但许可卡商用 |

> Kokoro 的中文音色名和微软那四个一模一样，不是巧合：它就是拿那批数据蒸馏的。
> 所以听感**接近但不等于** edge-tts —— 好处是完全离线、免费、可商用。

## 三、克隆类（要 GPU，本机不适用）

|---|---|---|---|---|
| GPT-SoVITS | MIT（可商用） | 5s 零样本 / 1min 微调 | RTF 0.028（4060Ti） | 相似度天花板，但要卡 |
| IndexTTS-2.5 | 自定义协议，商用需授权 | 单参考音频 | 10s 语音约 2s（4090） | 6GB 显存起步，核显不行 |
| F5-TTS | 代码 MIT / **权重 CC-BY-NC** | 数秒 | RTF 0.04（L20） | 非商用，直播若挂礼物/带货要谨慎 |
| Fish Speech | Research License（**非商用**） | 10~30s | 流式 | 音质好，许可卡死商用 |
| OpenVoice V2 / XTTS-v2 | MIT / CPML（非商用） | 10s / 6~15s | 中 | 中文效果弱于上面几个 |

## 四、还有一条野路子：RVC 变声

把 edge-tts 合成好的音频过一遍 RVC 声线模型，等于「用微软的发音 + 别人的音色」。

- 优点：CPU 也能跑（几百毫秒级），不挑嗓子，B 站一堆现成模型。
- 缺点：延迟 +0.3~1s（直播里能听出来）、音质有损、齿音重；
  而且社区模型多是翻唱/真人声音，**版权和肖像权风险自己担**。
- 对本项目：会破坏现在「缓存命中即 0 延迟」的优势（缓存的是变声前还是变声后要重新设计）。

## 五、我的建议

1. **主线继续用 edge-tts**。音质天花板、零成本、已经有缓存体系。设置页现在能换的
   四副嗓子（晓晓/晓伊/晓北/晓妮）+ 语速 + 音高，日常够用。
2. **想离线兜底就上 Kokoro-82M v1.1-zh**。它能在你这台机器上跑进实时，Apache 许可可商用，
   断网也不会哑，**v1.1-zh 还自带约 50 个中文女声**。做法：`tools/tts.py` 加
   `--backend edge|kokoro|piper`，`cache/media.json` 的 `tts` 段多一个 `backend` 字段，
   设置页加个引擎下拉。⚠️ 但装依赖有坑（Python 3.13 + torch 下载），先看第六节。
3. **想真的「换一个人」就只能加显卡**（8GB 显存起步），再上 GPT-SoVITS / CosyVoice。
   纯 CPU 这条路走不通，别在这上面花时间。

如果决定上 Kokoro，我先跑一组实测：同样一句话，edge vs kokoro 的
合成耗时、缓存命中率、听感对比样音，再决定要不要把它做成可选引擎。

## 六、实测记录：Kokoro 这次没装上（如实写）

2026-10-30 晚真跑了一遍，卡在环境上，没拿到样音。过程记下来，省得下次重复踩：

1. **项目 venv 是 Python 3.13**。`pip install kokoro` 会把 numpy 拉到需要源码编译的版本
   （3.13 上没有对应 wheel），本机没有 MSVC/clang → `metadata-generation-failed`。
2. **换 Python 3.12 建沙盒**：`kokoro` + `misaki[zh]` 依赖解析直接冲突 ——
   新版 misaki 已经**不提供 `zh` 这个 extra**（`WARNING: does not provide the extra 'zh'`），
   必须去掉 extra 单独装。
3. `--only-binary=:all:` 能绕开源码编译，但 `jieba` 只有 sdist，会当场失败。
4. 最后 `pip install torch kokoro` 依赖能解析，**但 torch 的 wheel 下不动**：
   PyPI 官方源 16 分钟没完成，换清华源又 12 分钟没完成，只能先停。

**所以结论从「推荐」降级成「值得试，但要先解决环境」**：

- 用 Python 3.11 / 3.12 建独立 venv（别用项目的 3.13）；
- 先单独把 torch 的 CPU wheel 下好（离线 whl / 多线程下载），再 `pip install kokoro`；
- 装的时候**不要带 `[zh]` extra**；
- 依赖齐了直接跑 `.tmp/kokoro_try.py`（脚本已写好，会输出 7 个音色样音 + RTF）。

装好之前，想多几种女声只有两条现实路径：**语速/音高组合**（设置页已给 7 个预设）
和**台湾腔那两副嗓子**（`zh-TW-HsiaoChen` / `HsiaoYu`，已加进下拉）。
