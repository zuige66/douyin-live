# 2026-10-29 对话改造：从「问答机」到「能接话」

主人原话：「我感觉现在回答有点太无聊了」。

先说结论：**不是话术不好，是链路上根本没有「对话」这个东西**。
每条弹幕都是独立请求（system 人设 + 一条 user 行），她不知道上一条说了什么。

## 一句话诊断

2026-10-29 18:03–18:10 的真实弹幕可以当证据：

```
18:04:20 森波拉：你认识汤令山吗
18:04:43 森波拉：汤令山是唱颜色的      ← 补充说明上一条
```

在她那儿，这两句是两个陌生人说的。第一句答完「认识呀」，第二句又从零开始 ——
观众体感就是「这 AI 不太聪明」，她不无聊，她是断线的。

---

## 一、3 轮对话历史（A）

**改了什么**

`bridge.mjs` 新增 `dialog` 环形缓冲，只存**真正说出口**的话：

```js
const DIALOG_ROUNDS = 3          // 3 组 = 6 条消息
const dialog = []                // [{role, content}]
```

`replyWorker` 每次调 `makeReply({...ctx, history: dialog.slice()})`，
`reply.mjs` 的 `llmReply` 把它拼成真 messages：

```js
[{role:'system', ...}, ...history, {role:'user', content: 当前这句}]
```

**为什么 history 放在 system 后面**

deepseek 的前缀缓存是从第一条消息往后算的。把人设塞进 system 才命中，
history 放后面只让「history + 当前这句」这一段不命中 —— system 那 2000 多 token 照命中。

**进历史的只有 chat / gift / chitchat。**
`welcome`（进场）和 `like`（点赞）不进：量大、信息少，塞进去只会把真正的对话挤掉。

**顺带去掉了 `saidHint()`**
它记的是「最近说过的 3 句」，跟 history 里的 3 条 assistant 完全重复。
现在只有不带历史的那条路（面板「试说一句」、启动探活）才用它。

---

## 二、聊天队列 1 条 → 3 条（A 的必要前提）

只加历史不改队列会更乱：她答完 A，B 被 C 顶掉，历史里就成了 C 直接接 A 的回答。

```js
const CHAT_QUEUE_MAX = 3
const chatQueue = []   // FIFO，满了 shift() 掉最老的，并且打日志
```

取用顺序也改了（主人定）：

```
礼物 > 点歌 > 聊天 > 点赞
```

原来点赞排在聊天前面，理由是「点赞被节流过，攒很久才轮一次」。
但实际观感是：有人说话她被晾着，去谢一个飘过去的爱心。

---

## 三、同句去重 60 秒 → 15 秒

```js
const SAME_TEXT_MS = 15000
```

60 秒那道闸门本意挡刷屏，实际把正常重复也吃掉了 ——
观众一句「好听」隔半分钟再说一次，她当没看见。

15 秒足够挡「一个人狂刷同一句」。这条只管**同人同句**，不同人不受影响。

## 四、20 字截断：从「砍后半句」改成「保住结论」（C1 + C3）

### C1：往哪边砍

原来的 `clip()` 是「从前往后找到最后一个句读就断」，断出来的一定是前半句：

```
「不是双一流，但控制科学是A-，广东就这一家」
  → 旧：「不是双一流，但控制科学是A-」   ← 结论被扔了
  → 新：「但控制科学是A-，广东就这一家」
```

现在两步：

1. **先砍铺垫**（`LEAD_RE`）：「我跟你说」「其实呢」「说实话」「讲真」……
   砍完不超长就直接返回；
2. **从后往前贪心拼**：按句读切小句，从尾巴往上累加，拼到再加一句就超长为止。

保险：保下来的不足原句一半时不敢这么砍（会留下没主语的半句），退回老逻辑。
没有句读可切时才硬切。

### C3：深度问题放到 40 字，拆两句说

```js
const MAX_LEN_DEEP = 40
export function needDeep(text)   // 为什么 / 怎么看 / 说说 / 认识××吗 / 区别 / 看法…
```

命中就 `maxLen = 40`（`max_tokens` 跟着提到 200）。
桥那边用 `speakSplit(text)` 拆成两段，**分两次上字幕、两次合成**：

```js
for (每段) {
  await ttsSynth(段)
  broadcast('say', { text: 段, part: i+1, parts: n })
  playFile()
  if (!最后一段) await sleep(max(900, 时长 + 120))   // 等这段念完再上下一段
}
```

不等的话字幕先跳到后半句、声音还在念前半句，观众看着就是错位。

> 🔴 **光放宽 `clip` 的上限没用**。第一版就是这么写的，实测模型还是只回 16 个字
> （「数字生命啊，我觉得…诶，这题好大」）—— 人设卡的铁律写着「一句话 20 字以内」，
> 它老老实实照做了。必须在 **user 行里显式覆盖**一次：
> `（这条可以多说一句：最多两句、40 字以内…）`。加完立刻变成 26 字、正常拆两段。
> system 一个字都没动，前缀缓存照命中（实测 93.1%）。

**注意**：字幕条 900px / 34px 只放得下 21 字，所以 40 字必须拆，不能改一条。
单段的（绝大多数）走的还是原来那条路，一个字都没变。

## 五、冷场素材（B）

原来冷场她只会说「突然这么安静，都在忙吗」—— 因为她**什么都不知道**。

现在 `buildFacts()` 把现场能看见的拼给她：

| 素材 | 来源 | 有效期 |
|---|---|---|
| 在放什么歌 | `music.title` / `music.artist` | 5 分钟内 |
| 刚谁送了什么 | `lastGiftName` / `lastGiftAt` | 5 分钟内 |
| 几个人在看 | `stat.online` | 实时 |

同一素材 **10 分钟内不重复**（主人定，`FACT_REPEAT_MS`）。
不卡的话一首歌放三分钟她能提四次，立刻变报幕。

`userLine` 的 chitchat 分支拼成：

```
直播间这会儿没人说话。你自己找个话头说一句…
（现场实况：正在放《雨爱》（司南）；刚才有人送了小心心。挑其中一件说，别把这几件都报一遍。）
```

**只在 `kind === 'chitchat'` 时才调 `buildFacts()`** ——
`factFresh()` 会消耗「新鲜度」，每句都调的话素材会被普通回复吃光，真冷场时反而没得说。

## 六、通用接梗（D）

「没命中的句子」本来就走模型，只有模型那条路断了才落到本地兜底。
原来兜底是「嗯嗯，我在听」—— 万金油，跟观众说的话一个字都不沾。

现在先**复述关键词**（`kwOf()`：去标点、去虚词，取前 8 个字）：

```
红烧肥鱼      → 「红烧肥鱼，诶这个有意思」
伪装成cloud了 → 「伪装成cloud啊，我得想想」
```

抽不出关键词才退回 `personaSamples()` → 最后才是「我在听」。

顺手把 `RE.ask` 的三句敷衍换掉了：

| 旧 | 新 |
|---|---|
| 这个问题问得好… | `{关键词}啊，我得想想` |
| 你猜猜看 | `{关键词}这个，我说不太准` |
| 让我想想，别催我 | `你问{关键词}，我脑子转不过来` |

观众认真问一件事，至少得证明她真看了这句话。

## 七、素材视频的梗话（E）

主人要：「放素材视频的时候可以说一句梗话，播放完也可以说一句」。

**永远走本地，不走模型**，两个原因：

1. 模型不知道这段视频拍的是什么，只能瞎猜，猜错了比不说更尴尬；
2. 视频已经开始放了，观众最需要「马上有反应」，等模型两秒就凉了。

台词按**文件名**配（素材名本身就是梗），见 `reply.mjs` 的 `CLIP_LINES`：

| 素材 | 开场 | 收尾 |
|---|---|---|
| `0-优势在我.mp4` | 优势在我，这波稳了 | 看到没，优势在我 |
| `0-梁圣巡演.mp4` | 梁圣巡演，前排坐好 | 散场了，还在回味 |
| `2-man.mp4` | Man，what can I say | 凌晨四点，我服了 |
| `4-瑞克摇.mp4` | Never gonna give you up | 你被 rick 了，嘿嘿 |

没配上的走 `CLIP_GENERIC`。**新增素材只加一行，别的代码一个字不用改。**

挂载点：

- `mediaBegin()`，`tier === 0` 且**不是观众点播** → 排一句 `videoIntro`
- `mediaFinish()`，`why === '播完'` 且队列里没有下一段 → 排一句 `videoOutro`

三个「不说」：

1. **观众点播不排开场** —— 那一路 `replyWorker` 本来就会回一句「行，放一段」，
   再来一句开场等于同一件事说两遍；
2. **不是正常播完不说收尾**（超时 / 被她说话打断）—— 观众还没看完就评价更怪；
3. **开场话有时效**：`replyWorker` 是串行的，前面压一条点歌能卡十几秒，
   等轮到它视频已放一半 —— 超过 8 秒直接丢。

面板「试播」传 `silent: true`，不会触发。

## 参数速查

| 参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `DIALOG_ROUNDS` | `bridge.mjs` | 3 | 对话历史轮数（1 轮 = user+assistant） |
| `DIALOG` 队列 | `bridge.mjs` | 3 | 聊天 FIFO 上限 |
| `SAME_TEXT_MS` | `bridge.mjs` | 15000 | 同人同句去重窗口 |
| `FACT_REPEAT_MS` | `bridge.mjs` | 600000 | 同一素材不重复 |
| `CHAT_GAP` | `bridge.mjs` | 2500 | 两条聊天间隔（设置页可改 0.5~15s） |
| `MAX_LEN` / `MAX_LEN_DEEP` | `reply.mjs` | 20 / 40 | 普通 / 深度问题字数 |
| `CLIP_LINES` | `reply.mjs` | — | 素材视频台词表 |

## 怎么验证

```bash
node --check bridge.mjs && node --check reply.mjs

# 截断策略
node -e "import('./reply.mjs').then(m=>console.log(m.clip('不是双一流，但控制科学是A-，广东就这一家')))"

# 素材台词 / 深度判断 / 拆句
node -e "import('./reply.mjs').then(m=>{
  console.log(m.clipLine('0-优势在我.mp4','intro'))
  console.log(m.needDeep('说说你对于数字生命的看法'), m.needDeep('这首歌真好听'))
  console.log(m.speakSplit('不是双一流，但控制科学是A-，广东就这一家，别的学校比不上'))
})"

# 本地兜底（不花 token）
node -e "import('./reply.mjs').then(async m=>console.log(await m.makeReply({kind:'chat',user:'卡普o',text:'红烧肥鱼',forceLocal:true})))"
```

直播里看日志：

- `🗣 xxx（拆 2 段）` → 深度问题走了两段
- `[clip] 保住结论断到 N 字` → 截断按新策略生效
- `💬 聊天排满 3 条，丢掉最早那条：xxx` → 队列真在丢，看得见丢的是谁
- `🖥 开场话排太久（视频已放一半），跳过` → 时效保护生效

## 代价

- 每条模型请求多约 150~200 token（history）。system 命中率不受影响。
- 深度问题会多一次 TTS 合成 + 约 0.4 秒间隔。
- 视频开场/收尾各多一句，闲时视频连着放时会多几句话（同一段 10 分钟内不重复）。
