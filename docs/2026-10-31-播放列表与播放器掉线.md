# 播放器页加播放列表 + 「播放器连不上」的根因（2026-10-31 晚）

## 一、播放列表（`music.html`）

### 加在哪

控制台左侧「播放器」那一页（`music.html`，挂在 `index.html` 的 iframe 里）。
在主卡片下面新起一张「播放列表」卡片，接着音量条那一行往下。

### 数据从哪来

`/state.json` 的 `queue` 字段（`bridge.mjs` 第 6615 行那个对象）：

```js
queue: {
  total: boxQueue.filter((x) => !x.hot).length,   // 真人点的首数（不含热榜垫的）
  why:   queue.why || '',                        // 队列空着的原因
  list:  boxQueue.map((x) => ({
    name: x.name,
    hot:  Boolean(x.hot),                        // 热榜垫的 / 真人点的
    sec:  Math.max(0, Math.round((Date.now() - x.at) / 1000)),
  })),
}
```

⚠️ **`sec` 是「这首歌排了多久」，不是歌曲时长。** 它是 `now - at`，
不是 `duration`。所以列表右边那列写的是「等了 2:15」，不是「时长 3:19」。
第一版很容易搞错这个，显示出来就是一堆 `0:00`。

⚠️ **`list` 不含正在放的那首**，是「接下来要放的」。当前曲目在上面的封面卡片里。

### 实现要点

```js
const esc = (s) => String(s).replace(/[&<>"']/g, c => ({...}[c]))

function paintQueue(q) {
  const key = list.map(s => s.name + '|' + s.hot + '|' + s.sec).join(',')
  if (key === lastQKey) return      // 没变就不重画
  lastQKey = key
  // ...渲染 li
}
```

两条必要的防护：

| 防护 | 为什么 |
|---|---|
| `esc()` 转义歌名 | 歌名是观众打的。一个 `<img onerror=...>` 就能在控制台里执行 —— 那是主播自己天天开着的页面 |
| `lastQKey` 比对 | 3 秒刷一次，不比对的话每 3 秒重建 DOM，hover 高亮和滚动位置一直闪 |

刷新节奏从 5 秒改到 **3 秒**（点完歌要盯着列表看有没有进去，5 秒太钝），
另外点「上一首/下一首/播放」之后立刻手动刷一次，不用等下一个周期。

样式全部走 `/ui/theme.css` 的变量（`--surface-1/2/3`、`--on-variant`、`--primary-c`），
没引入新颜色，跟其它页保持一致。

## 二、「播放器连不上超过 25 秒」的根因

日志原文：

```
21:20:23  ♫ 播放器连不上超过 25 秒（播放器界面没开），音乐回落到本机 QQ 音乐
21:20:40  ♫ 自检：播放器一直连不上，已重扫 DSH 端口
21:20:48  ♫ 音乐切到单身汉播放器（DSH 内播放）    ← 又自己回来了
```

### 判活是怎么判的

- `player/musicd.mjs`：`ALIVE_MS = 8000`，`alive = Date.now() - S.clientAt < 8000`
- `S.clientAt` 由 `/client/poll` 打（页面每秒一次）
- 桥每轮检查，`clientAlive` 为假超过 **25 秒**宽限就切本机 QQ 音乐

### 真正的坑：解锁失败会把心跳一起停掉

`index.html` 的 `auTick()`：

```js
async function auTick() {
  if (auPolling) return
  /* 没解锁就一次都别发 */
  if (!musicUnlocked) return      // ← 心跳也在这里停了
  ...
  const r = await mApi('/client/poll?unlocked=' + ...)
}
```

而 `musicUnlocked` 会在**切歌时被置回 false**：

```js
try {
  await au.play()
  musicUnlocked = true
} catch {
  musicUnlocked = false    // 浏览器拒绝自动播放
  paintMusic()
}
```

于是链条是：

```
某次切歌 au.play() 被浏览器拒 → musicUnlocked = false
      ↓
auTick 直接 return → 再不发 /client/poll → clientAt 不更新
      ↓
25 秒后桥判定「播放器界面没开」→ 切本机 QQ 音乐
      ↓
观众那边：音乐没了
```

**页面明明开着，只是那一次 play() 没成功。** 这跟「界面没开」是两回事，
但桥看不出来 —— 它只有一个心跳可看。

### 三种触发场景

1. 浏览器自动播放策略：页面刷新后没点过任何东西，`play()` 会被拒
2. 控制台标签在后台：Chrome 把 `setInterval` 节流到 1 分钟一次，心跳自然断
3. 页面被关掉（这个是真没开，属于正常回落）

### 怎么修的（21:57 已上线）

心跳和「取命令」拆开。原来是一个接口干两件事，`/client/poll` 取走即清空，
所以未解锁时不能发 —— 会把 18083 那个独立播放页的命令偷走。

**`player/musicd.mjs`** 加一个 `peek=1`：

```js
S.clientAt = Date.now()
const q = url.searchParams
if (q.has('unlocked')) S.clientUnlocked = q.get('unlocked') === '1'
const peek = q.get('peek') === '1'
const cmds = peek ? [] : S.commands.splice(0, S.commands.length)
return json(res, 200, { commands: cmds, volume: S.volume, nowPlaying: nowPlaying() })
```

`peek` 时**一个命令都不拿**，但 `clientAt` 照样打 —— 桥只看心跳，就认为界面还在。

**`index.html`** 的 `auTick()`：

```js
if (!musicUnlocked) {
  auPolling = true
  try { await mApi('/client/poll?peek=1') }
  catch { /* 播放器服务没起来时不要刷屏 */ }
  finally { auPolling = false }
  return
}
```

用了 `auPolling` 锁，避免 peek 请求在网络慢的时候每秒堆一个。

**重启方式**（别直接杀进程，用主控的接口，它负责拉起并写 pid）：

```bash
curl -X POST http://127.0.0.1:18082/ctl/music \
  -H 'Content-Type: application/json' -d '{"action":"restart"}'
```

⚠️ **重启会丢当前队列** —— `musicd` 是无状态的，队列只在内存里
（`server.mjs` 那句注释：「它是无状态的，重启会丢当前队列」）。
重启后桥会自动 `maybeHot()` 把热榜垫回来，但观众点的那几首没了。

### 实测

```
重启：pid 33336 → 73204，{"ok":true,"message":"播放器服务起来了"}

peek 测试：
  GET /client/poll?peek=1  →  {"commands":[],"volume":0.7,...}   ← 不取命令

4 秒后 /state：
  clientAlive: True   clientUnlocked: True   playing: 还是会想你

12 秒后桥端：
  music: {"on":true,"playing":true,"title":"还是会想你"}
  日志：♫ 热榜垫上《还是会想你》《我好像在哪见过你》《我好想你》
  —— 队列被重置后自动垫回来了，没有出现「播放器连不上」
```

⚠️ **浏览器页面要刷新一次新 JS 才生效**。`musicd` 那边重启即生效（服务端），
但 `index.html` 的 `auTick` 改动在页面里，不刷新还是旧逻辑。
