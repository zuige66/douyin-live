# 画面编辑器：只保存才推送 + 多场景（2026-11-01）

主人原话：

> 编辑页面不要马上刷新到直播窗口，现在就是这样，改成保存后才刷新；
> 我后如果点击左上角刷新的话就是重置恢复。然后可以我是编辑多个页面，
> 然后选择使用哪个页面，因为我选择不同场景的。

三件事，一次做齐。

---

## 1. 改 → 只存草稿，不推给画面

**以前**：`editor.html` 里有个 `autoSave()`，任何一次拖动/改字号后 400 毫秒防抖
就 `POST /layout`。也就是说**手一抖，观众就看见了** —— 拖到一半的框、试颜色的那种
中间态，全都实时播出去。而且 15 处编辑回调都在调它，光把按钮藏了没用。

**现在**：`autoSave()` 改名 `markDirty()`，只做两件事：

1. `localStorage['zhibo.layout.v2']` 写一份（防手滑刷新）
2. 顶栏胶囊亮「未保存 · Ctrl+S 推送」

推送只发生在**点「保存并推送」或按 Ctrl+S**（`save()` → `POST /layout`）。
按钮也改了名：`保存到画面` → `保存并推送`，字面上就说清楚它会推到直播。

## 2. 刷新 = 重置

- `boot()` 先用草稿把界面点亮（桥没起时不至于白屏），**桥一答应就整份换成
  `GET /layout` 那份**。所以 F5 之后看到的一定是画面正在用的版式。
- 「重新载入」按钮：确认 → 删掉草稿 → 重新读画面。等于手动版的 F5。
- 按错 F5 不该赔掉半小时的活，所以留了个**「恢复草稿」**按钮：
  只在「草稿和画面不一样」的时候出现，点它把草稿捡回来（仍是未保存状态，
  要推还是得自己点保存）。编辑过一次之后它就自动收起，不再唠叨。

## 3. 多场景

### 存储

```
cache/layouts/<id>.json      每个场景一份完整版式（内容 = 一份 layout.json）
cache/layouts/index.json     { active:'<id>', list:[{id,name,at}] }
cache/layout.json            🔴 永远是「当前生效那份」的镜像
```

**`native/render.py` 一个字都没改。** 它只认 `cache/layout.json`、只 stat 它的
mtime，所以「切场景」= 把场景文件原子覆盖到 `layout.json`，画面自己会发现并在
1 秒内重建静态层。这是这件事能做得这么小的唯一原因。

镜像两个方向都要：

- 切场景 / 保存 / 另存为 → 写 `layout.json` **并**镜像回生效场景
- 换皮套（`POST /pet`）→ 也走 `writeLiveLayout()`，否则切走再切回来皮套会退回旧的

反例（已避免）：只写 `layout.json`、不回头更新场景文件，那么 A→B→A 之后
A 上刚改的东西全丢，而人完全看不出发生了什么。

### 接口（`bridge.mjs`）

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/layout/scenes` | `{active, list:[{id,name,at}], dir}` |
| POST | `/layout/scenes` | `{name, layout?}` 另存为新场景并**立刻生效** |
| POST | `/layout/scene/activate` | `{id}` 切场景（原子覆盖 layout.json） |
| POST | `/layout/scene/delete` | `{id}` 删场景；删的正好是生效那份时**不动** layout.json |

- `GET /layout` 的返回里多了 `scene:{id,name}`，编辑器用它显示「已同步 · 打游戏」。
- **首次使用自动收编**：`/layout/scenes` 发现索引是空的、而 `layout.json` 有内容，
  就把它存成场景「默认场景」并设为生效。不做这一步的话，下拉框是空的、看着像坏了。
- 同名「另存为」覆盖原场景，不攒一串同名项。
- 场景 id 只允许 `[a-z0-9_-]`（它就是文件名）；`../../etc/passwd` 这种直接被拒。

### 编辑器操作

顶栏左侧：

```
场景 [下拉 ▾] [另存为…] [删]
```

- 下拉里列全部场景，当前生效那个就是选中的。**换选项 = 直播间立刻换版式**，
  所以会先弹一句确认（顺带提醒「没保存的改动会丢掉」）。
- 另存为…：输入名字 → 存成新场景并切过去（不用再点一次切换）。
- 删：删掉当前场景，画面保持原样不变（不黑屏）。只剩一个时拒绝删。

## 踩过的坑

- **顶栏被挤成竖排**：加了场景栏之后，1280 宽窗口里 flex 把按钮压扁，
  「另存为…」变成三行竖字。修法是 `.btn{white-space:nowrap;flex:0 0 auto}` +
  顶栏 `overflow-x:auto`（不够宽就横向滚），再加一条 `@media (max-width:1400px)`
  把「缩放 / 50%」那几个字让出去。
- **下拉选项里塞时间会被截断**：`打游戏 · 11-01 15:47` 在下拉框里显示成半截，
  看着像坏了。现在选项只写名字，时间放 `title`。
- **草稿和「恢复」的关系**：编辑时把按钮收起（`markDirty()` 里 `showDraft(false)`），
  否则边拖边亮「恢复草稿」，人会以为自己存错了。

## 怎么验的

不是"看着没问题"，是真跑过：

1. 桥起在备用端口，`curl` 走完 另存为 → 保存 → 切场景 → 删 → 非法 id → 删最后一个；
   并对比 `layout.json` 与测试前备份**逐字段完全一致**（`sanitizeLayout()` 不丢字段）。
2. 无头 Chrome 加载真编辑器：
   - 编辑一像素后顶栏 = 「未保存 · Ctrl+S 推送」，`localStorage` 有草稿，
     而桥日志里**没有** `[layout] 版式已保存` —— 证明没偷偷推。
   - 再点「保存并推送」，桥日志出现一条 `版式已保存（…，场景「默认场景」）`。
3. 先塞一份 x=777 的假草稿再加载：画面显示的是生效版式（不是 777），
   「恢复草稿」出现；点它 → 变「未保存」，按钮收起。
4. `window.onerror` 全程为空；1560 宽下顶栏不溢出。

## 还没做的（想做再加）

- 场景**复制**、导出/导入（场景文件就是 JSON，手动拷 `cache/layouts/` 也行）。
- 编辑器的「保存」只推当前场景；如果主人想「一次推全部场景」，那是另一个开关。
