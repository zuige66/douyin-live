### ② 白色边框 —— 不是配色问题，是渲染 bug

`native/render.py` 里 `img.paste(patch, xy)` **少了 alpha 遮罩**，
所以 `(255,255,255,26)` 这种 10% 的白描边被当成**不透明纯白**贴上去。
截图里量出来是 `(255,255,255)` 满值 —— 你的眼睛没骗你，它就是纯白。
圆角外侧也被一起贴成死黑。

修法：`img.paste(p, xy, p)`（新增 `blit()` 统一走带遮罩的贴法）。
顺带：
- 描边全去掉（10% 白在视频转码后最脏），改用**柔影**托底把气泡从背景里托起来
- 圆角 18→20，普通弹幕用户名改成低饱和青（原来满饱和青，满屏都在喊）
- 字幕条**按内容收窄**（原来定宽 900，短句右边空一大片），上限仍是 900

⚠️ 要**重开画面窗口**才生效（关掉现有的「zuige大肥鱼直播画面」，面板里点「开画面窗口」）。

理由：直播要的是"立刻出声"，0.39 秒和 2 秒是两种体感。音质差距在直播间的压缩码率下被抹平不少。

**要改的地方**
1. `bridge.mjs`：`queueReply` 里拿到回复 → 先 `say()` 出字幕 → 调 TTS → 播放
2. 新增 `tools/tts.py`：`--text` `--voice` `--out`，输出 wav/mp3
3. 新增 `tools/play.py`：MCI 播放，能报"还有多久放完"
4. **字幕停留时长 = 音频时长**（现在写死 6~8 秒，短的念完还在、长的没念完就没了）
5. 缓存：`sha1(文本+音色)` → `cache/tts/xxx.mp3`。常见短句（「在呢」「好听就多听几遍」）命中率很高，命中即 0 延迟

## 五、缓存命中率为什么「低」（实测，2026-10-26）

先给结论：**现在的 84.5% 已经是这条链路的天花板，不是配置错了。**

### 实测数据

同一个 key、同一个模型（`deepseek-flash`），把 `system` 换成不同长度的静态前缀，各打 3 次：

| system 长度 | 命中 | 输入 | 命中率 |
|---|---|---|---|
| 1494 tok（现用人设 2271 字） | 1280 | 1513 | **84.5%** |
| 2238 tok | 2048 | 2257 | 91.5% |
| 3010 tok | 2816 | 3029 | 93.4% |
| 39 tok（内置短人设） | 0 | 39 | 0% |

三条规律（三组长度都对得上，不是巧合）：

1. **命中 ≈ (system 长度 − 190) 向下取整到 64**。最后约 190 个 token 永远命不中
   —— 平台按 64-token 块算，尾部几个块不计入。这是平台行为，改不了。
2. **弹幕本体（约 19 tok）每条都是新 token**，必然 miss。
3. 所以命中率 = (前缀 − 190) / (前缀 + 弹幕)。**前缀越长比值越高。**

### 那「低」是怎么来的

平台那个数是**按天聚合**的，里面混着：

- 今天白天用的还是写死在代码里的**八行短人设**（约 100 tok，压根不够凑一个 64 块）⇒ 那阵子几乎全 miss
- 每次改 `prompts/dafeiyu-live.md`，下一条请求**整段前缀全废**（改一次全 miss 一次）
- 每次重起 bridge，第一条也是全 miss（缓存几小时不碰会掉）
- 同一个 key 上跑过的探针/实验/别的工具

### 已经做的改动

- `reply.mjs` 加了**缓存账本**：每条请求记 `prompt_cache_hit_tokens`，第 1 条和每 10 条打一行
  `[cache] 本条 1280/1510（84.8%）· 累计 …`
- `bridge.mjs` 的 `/healthz` 多一个 `cache` 字段：
  `curl -s 127.0.0.1:18081/healthz | python -m json.tool`（看 `cache.rate` / `cache.last`）
- `node reply.mjs --warm`：开播前跑两次，第一条弹幕就不用全价买 1494 个 token

### 想再往上提，只有三条路

1. **把固定内容往 system 里塞，别往 user 里塞**（对照表、口头禅、常见问题答案都算）。
   但这只是**把比值做好看** —— 多塞的 token 即使 9 折命中，也比不塞更贵。
   实测：前缀 1494→3010 后，单条等效全价 token 从 361 涨到 481。**别为了命中率而命中率。**
2. **减少请求数**（这才是真省钱）：礼物、点歌已经走本地模板；下一步可以给
   「同一个人 60 秒内刷同一句」去重、`666`/`哈哈哈` 这类不点名的走本地。
3. **别把会变的东西塞进 system**：时间、在线人数、最近弹幕、队列状态。
   一旦塞进去命中率当场归零，而且日志里看不出来 —— 这是以后加「冷场找话」时最容易踩的坑。
   要带上下文就放 user 消息里，system 必须**逐字节不变**。

一句话：命中率 84.5% 不用管，**该盯的是每小时请求条数**。

## 六、2026-10-27 凌晨：五个反馈的处理

### 1. 语速太快 → `+8%` 改成 `-8%`

- `bridge.mjs` 的 `TTS_RATE` 默认值、`tools/tts.py` 的 `DEFAULT_RATE` 都改了
- 实测同一句 4.06s → **4.75s**（慢了 17%）；再慢一档 `-15%` 是 5.14s
- 想自己调：`REPLY_TTS_RATE="-15%"`（改完要清 `cache/tts` 吗？不用，缓存 key 里带语速）
- 🔴 顺手修了一个坑：argparse 会把 `-8%` 当成选项，`--rate -8%` 直接报错。
  现在 `tts.py` 会先把这种写法改写成 `--rate=-8%`，桥里也统一用 `=` 形式

### 2. 大肥鱼突然没了 → 是真的 bug，已修

**根因**：冷场定时器把 mood 切到 `yawn`/`stretch`，但这两段**当时根本没下帧**
（`assets/pet/idle_yawn` 是空目录）⇒ `pet.frame()` 返回 `None` ⇒ 渲染层什么都不贴。
表现就是"人突然消失，过几秒又出来"。

三层修法，任何一层都能兜住：

1. `pet.clip_for()`：mood 指到没下帧的动作，**一律退回 idle**
2. `pet.frame()`：拿不到帧也退回 idle
3. `render.draw_character()`：整段包 try/except，出任何异常都退回静态立绘

另外把缺的 7 段动作全下了：`idle_yawn` `idle_stretch` `thinking` `waiting` `head_pat` `tail` `poke`
（各 241 帧，共 40MB）。现在 11 种 mood 全都有对应动作。

### 3. 变模糊 → 放大后加 3×3 锐化

素材里角色只有 222px，放到 570px 是 2.57 倍放大，不处理就是一团糊。

- 试过三种：先锐化再放大 8.8ms（边缘发脏）、放大后锐化 20.7ms（**明显更脆，采用**）、UnsharpMask 140% 19ms（更贵但没更好）
- 只锐化 RGB、alpha 原样保留 —— 连 alpha 一起锐化会在轮廓外啃出白边
- 代价：逐帧从 22.7ms 涨到 34.4ms，10fps 下单核 34%（14 核合计约 2.4%）
- 关掉：`ZY_PET_SHARP=0`；还嫌糊只能上 Real-ESRGAN 离线放大（一次性 20 分钟 + 60MB 依赖）

### 4. 表情跟着"有人说话/有人来"变

`bridge.mjs` 里 `noteEvent()` + `setMood()`，画面每 0.4 秒拉一次 `mood`：

| 触发 | mood | 播哪段 |
|---|---|---|
| 默认 | idle | 待机呼吸 |
| 有人进直播间 | `waiting` | 抬头张望 3.4s |
| 收到礼物 / 被夸 | `happy` | 雀跃 4.2s |
| 被骂（笨/丑/滚/垃圾…） | `sad` | 委屈 5.2s |
| 正在想怎么回 | `thinking` | 思考冒泡 4.2s |
| 安静 40s+ 且刚说过话 | `yawn`/`stretch` | 打哈欠 / 伸懒腰 9.2s |

### 5. 会自己开口了（欢迎 + 自言自语）

`reply.mjs` 新增两种 `kind`，本地话术和模型两条路都支持：

- `welcome` —— 有人进来，欢迎一句（`${user} 刚进直播间。欢迎一句，别太热情，也别问问题。`）
- `chitchat` —— 安静太久，自己找话头（`直播间这会儿没人说话。你自己找个话头说一句，不要提问，不要喊人。`）

**频率闸门（这是重点，不然会变复读机）**

| 闸门 | 值 | 改法 |
|---|---|---|
| 安静多久才考虑开口 | 40s | `REPLY_QUIET_FOR_TALK` |
| 两次主动开口最小间隔 | 90s | `REPLY_SELF_GAP` |
| 两次欢迎最小间隔 | 25s | 写死（进出太频繁） |
| TTS 还在出声 | 一律不动 | 写死 |

说不了话（刚说过）的时候，让画面动一下（哈欠/伸懒腰），至少不像死机。

实测（把闸门压到 3s/8s 跑 24 秒）：
```
00:31:32 [self] 安静 5s，自己找句话
00:31:34 🗣 我给你们念念我围裙上这只小鲸鱼。
00:31:52 [self] 安静 5s，自己找句话
00:31:54 🗣 头发梳到一半，尾巴先晃起来了。
```
