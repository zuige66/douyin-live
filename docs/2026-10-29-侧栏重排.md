# 侧栏重排：11 个页签 → 6 组，扁平 9 项

2026-10-29 下午。起因是一句话：「设置里面的东西太多了，可以放出来一级」。

## 先搞清楚病因

数了一下才发现问题不在嵌套，在内容量：设置页 11 个页签底下共 **33 张卡片**。

所以只有两个杠杆 —— **减少点击深度**，或者 **减少主题数**。摊平不减少条目，
删条目会丢功能。当时摆了三个方案：

| | 做法 | 行数 | 点「声音」 | 代价 |
|---|---|---|---|---|
| A 分组扁平 | 解散设置，11 个页签分 5 组全部一级 | 15→19 | 2 跳 → 1 跳 | 侧栏变长 |
| **B 合并瘦身**（选了这个） | 重叠的页签合并成 6 个 | 15→9 | 1 跳 | 要动设置页结构 |
| C 只做减法 | 低频项收进折叠区 | 15→12 | 还是 2 跳 | 没解决问题 |

选 B。合并后又发现 6 个页签足够少，**不需要分组标题**，干脆全摊到一级 ——
所以最终行数比预估的 16 还少，只有 9 行。

## 合并依据：按「同一份数据」合，不按名字合

不是凑数字，是找真正互相依赖的：

| 新组 | 原页签 | 为什么能合 |
|---|---|---|
| **账号** | 账号 + 回复 | 都只在开播前调：房间号 + 回话档位/间隔 |
| **素材** | 礼物 + 电脑 | 「礼物名 → 档位」的档位参数就在「电脑」里，拆开看会两头找 |
| **形象** | 形象 + 人格 | 皮套人设和性格都是往 prompt 里拼的一段 |
| **记忆** | 记忆 + 知识 | 都是「她记得什么」：用户档案 + 知识库 |
| **声音** | 声音 + 音源 | 音量 + 谁在出声（网易云/QQ 登录、歌单） |
| **诊断** | 诊断 | 没得合，单独一个 |

合完最大的一组 7 张卡片，不会变成一坨。

## 怎么合的：卡片一张没搬

这是关键决定。搬 33 张卡片的 DOM 是几百行的高危操作，改成让**一个页签吃多个
section**：

```html
<button class="tab on" data-tab="account" data-sect="account,reply">账号</button>
<button class="tab"    data-tab="media"   data-sect="gift,computer">素材</button>
```

```js
const keys = (btn.dataset.sect || btn.dataset.tab).split(',')
const want = new Set(keys.map((k) => 'tab-' + k))
document.querySelectorAll('section[id^="tab-"]').forEach((s) => {
  s.classList.toggle('hide', !want.has(s.id))
})
for (const k of keys) runLoader(k)      // 两块各自的取数都要跑
```

`section` 的 id、顺序、卡片内容全部原样保留，所以 `loadGift()` `loadMedia()`
这些取数函数一行没改，只是可能被同一个页签连续调两次。

配套加了两件小事：

- 每个 `section` 挂 `data-label`，一屏里塞两块内容时（`body.multi`）在块前打一个
  分组小标题，用来分开「礼物」和「素材」。单块的一组（诊断）不打，少一行废话。
- 挂在外壳里时（`body.in-shell`）把页面自己那排页签和 `←` 藏掉 —— 侧栏已经有一份
  一模一样的了。直接双击打开 `settings.html` 没有这个类，还是原来的样子。
  页头标题也从写死的「设置」改成跟着分组走（「大肥鱼 · 声音」）。

## index.html 的菜单模型

`PAGES` 不再是一级菜单的数据源，新加了 `NAV`：

```js
const NAV = [
  { id:'panel',       hash:'#/panel',            name:'控制台', icon:'panel',   page:'panel' },
  { id:'set:account', hash:'#/settings/account', name:'账号',   icon:'account', page:'settings', tab:'account' },
  ...
  { sep:true },
  { id:'editor', ... }, { id:'music', ... }, { id:'set:diag', ... },
]
```

- **id 同时是多标签页的键**。以前按页面名记，设置里 6 个入口会挤成同一个标签；
  现在 `set:audio` / `set:media` 各是一个标签。旧的 `sessionStorage` 数据会被
  `BY_ID[k]` 过滤掉（`'settings'` 不是合法 id），自动降级，不用清缓存。
- **换组不重载 iframe**：只有 `page` 变了才动 `src`，同一页内换组走 `clickTab()`
  模拟点击。
- 侧栏底部用一道 `.sep` 把「日常」和「工具」分开，不另起分组标题。

## 顺带修的两个东西

**① `/state.json` 一直 403。** 「音源」里的歌单队列显示
「读不到：Unexpected non-whitespace character after JSON at position 4」。
根因在 `server.mjs`：静态文件放行检查**先看后缀、后看文件在不在**，
而 `.json` 不在白名单（为了挡 `llm.json` / `cookies.txt`）。可 `/state.json`
是桥现算的动态接口，磁盘上根本没这个文件 —— 被误伤成 403 纯文本，
`r.json()` 解析 "403 这个文件不给" 就报了那个位置 4 的错。

改成了先判断文件存在、不存在就交给桥，再看后缀：

```js
if (!fs.existsSync(fp) || !fs.statSync(fp).isFile()) return false   // 交给桥
/* 下面是原来的后缀白名单，对真实存在的文件照旧生效 */
```

验证：`/state.json` 200 + 真数据；`llm.json` / `cookies.txt` / `bridge.mjs`
仍然 403；`.run/` 下的文件仍然 403。

**② 命名。** 「电脑」→「素材」（那页全是素材区/档位/规则/闲时放，跟"电脑"无关）；
独立的「音乐」页 → 「播放器」（跟设置里的「音源」是两个东西，同名必然点错）。
正文里三处「在「电脑」页配」的提示也跟着改了。

## 验收

逐页截图看过：控制台 / 账号 / 素材 / 形象 / 记忆 / 声音 / 诊断 / 画面，分组小标题

**没验到的**：`music.html` 在 headless Chrome 下仍然崩渲染进程（`<audio>` +

侧栏（新标签打开）。它是**备用**出声方，平时不用开 —— 为什么、以及它以前怎么

## 退回

```bash
cp settings.html.bak-merge settings.html
cp index.html.bak-merge index.html
```

`server.mjs` 那处改动单独退回：把 `fs.existsSync` 那行挪回后缀判断之后。
