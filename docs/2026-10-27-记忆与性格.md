# 用户记忆 + 人格性格（2026-10-27）

> 需求原文来自「8. 新增：换装 + 成长值 + 用户记忆 + 人格性格系统」。
> **服装和成长值暂不做**，其余全做了。成长值/阶段字段在档案里留着空位，
> 以后接服装那套不用改存档格式。

## 一、先说清楚边界

| 需求 | 状态 | 说明 |
|---|---|---|
| 用户档案（昵称/时间/送礼/互动/标签） | ✅ | `cache/users.json` |
| 重启后保留、导出导入、清空 | ✅ | 面板 + API 都有 |
| 回应时体现档案（新人/老粉/榜一） | ✅ | 只进 user 行，不进 system |
| 三种性格（毒嘴/女仆/有梗） | ✅ | 接在人设卡**末尾** |
| 性格配置（称呼/口头禅/禁用词/示例库） | ✅ | `cache/persona.json` |
| 试说一句 | ✅ | `POST /persona/test` |
| 衣物换装、成长值折算、升级动画 | ❌ | 按主人要求先不做 |
| 展示区层级（角色 vs 礼物媒体） | ❌ | 已有礼物媒体，层级调整没动 |

**一处按主人要求改掉的需求**：原文女仆性格要称呼「主人/您」，
主人当晚拍板 **「不要叫主人，这是直播」**。所以三种性格的称呼统一是
「昵称或你」，女仆靠礼貌用语区分，不靠称谓。这条写进了性格定义和禁用词。

## 二、架构：三层，各有唯一真相

| 层 | 管什么 | 真相在哪 |
|---|---|---|
| 硬规则 | 不念广告、礼物必点名、点歌必报真队列 | 代码 |
| 风格内容 | 她是谁、怎么说话、什么性格 | 人设卡 + 性格段 |
| 状态事实 | 谁送的什么、最近说过什么、这个人是谁 | 代码 → user 行 |

以前「人设内容」被复制了一份到本地话术里（梗表两处手写），这次没有再复制：
**性格只写在 `reply.mjs` 的 `PERSONAS`，本地话术不跟**。
模型挂了的时候她只是变得简单，不会变成另一个性格。

## 三、用户记忆

### 主键：先说一个必须补的洞

`normalize()` 原来把 `user.id` 丢了，只留昵称。昵称会改、会重、带表情符号，
拿它当主键迟早串号。现在：

```js
function uidOf(d) {
  const u = G(d, 'user') || {}
  if (!u || !Object.keys(u).length) return ''   // 在线人数那种事件没有人
  const id = G(u, 'id')
  if (id) return String(id)
  return nick(d) ? 'n:' + nick(d) : ''          // 拿不到 id 才退回昵称，加 n: 前缀标出来
}
```

`n:` 开头的就是「没有 id 的弱主键」，以后发现串号一眼能看出是哪条路径。

### 存档

`cache/users.json`，跟 `money.json` / `gift.json` 一个套路：文件坏了当没有。

```json
{ "version": 1, "savedAt": 1793..., "users": [
  { "uid": "123", "nick": "阿伟", "firstAt": 0, "lastAt": 0,
    "chat": 12, "gift": 3, "like": 20, "member": 4, "song": 1,
    "growth": 0, "stage": 0,
    "tags": ["老粉"], "note": "唱歌好听",
    "gifts": [{ "name": "小心心", "n": 3, "at": 0 }] }
]}
```

三个设计决定：

1. **写盘防抖 1.5 秒**。一个人能连刷十几条弹幕，每条都写盘是白烧 IO。
   人为操作（改成长值/删档案/清空）走 `saveUsersSoon(true)` 立刻落盘。
2. **先写 `.tmp` 再 rename**。写到一半断电，盘上要么旧的完整文件、要么新的完整文件，
   不会留半个 JSON 把下次启动搞崩。
3. **上限 2000 人**，超了淘汰最久没来的，防止 json 涨到几 MB。

### 怎么用上

`pushEvent()` → `touchUser()` 记一笔并返回**这一次**的摘要（`isNew` 必须在写之前判断，
写完人人都不是新用户了）→ 摘要挂在 `ctx.profile` 上 → 回复引擎拼进 user 行：

```
阿伟 说：在吗。回他一句。
（这个人：老粉，来过 32 次，隔了 6 天才回来。别说这些数字，用话自然带出来，别像念档案。）
```

末尾那句叮嘱是实战加的：模型很爱把括号里的数字原样念出来，
直播间里就成了「你来过 12 次，送过 3 次礼」，像在念台账。

**档案读不到就按新用户走**，`profileLine()` 返回空串，绝不阻塞回话。

### 礼物档：必须点名

礼物感谢这次改成**走模型**（原来走本地模板）。原因是性格要有区别 ——
本地模板只有一种口气。代价是每条多等约 1 秒。

点名不靠模型自觉：出口有校验，回复里没有完整昵称就退回本地模板
（模板一定带名字）。实测 poison 性格第一句就漏了名字，被这条拦下。

## 四、性格系统

### 为什么接在末尾

prompt 缓存是**前缀**匹配。人设卡前 8 节三种性格共用，放前面就一直命中；
只有尾巴随性格变。换性格时失效的只是尾巴，不是整段前缀。

**没做三份独立卡**：三份要同步维护同样的铁律和红线，改一处漏两处，
最后三条性格的底线会各不相同 —— 那比风格漂移严重得多。

### 三套

| key | 名字 | 要点 |
|---|---|---|
| `poison` | 毒嘴 | 嘴硬心软，感谢带刺。刺是玩笑不是攻击。脏话/人身攻击/家人三条硬禁 |
| `maid` | 女仆 | 温柔有分寸，多说请和谢谢。**不叫主人**。禁命令口吻和谄媚 |
| `meme` | 有梗 | 反应快爱接梗，密度高一档，但老规矩不变：抛了才接、一次一个 |

每套都有一句兜底：**「以上只改说话的方式，铁律和底线一个字都不放松」**。

### 缓存账

`getSystem()` 每次重算（内容不变时字符串完全一样，缓存照样命中）。
顺手把欠了很久的**人设热重载**做了：人设卡按 mtime 缓存，
改完文件下一条弹幕就生效，不用重起桥。

## 五、设置页

新文件 `settings.html`，桥直接 serve，地址 `http://127.0.0.1:18081/settings.html`。
风格照抄 `music.html`（Material 3 dark teal，纯色无渐变）。

- **用户记忆**：搜索 → 列表 → 点开详情（标签/备注/成长值/删除）→ 导出/导入/清空
- **人格性格**：三选一 → 编辑口头禅/禁用词/示例库 → 试说一句

清空的二次确认写在**后端**（必须带 `confirm:"yes"`），不靠前端 —— 前端写错一次就全没了。

## 六、接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/user/list?q=&limit=` | 列档案（按最近活跃） |
| GET | `/user/get?uid=` | 单个档案 |
| POST | `/user/set` | 改标签/备注/成长值/阶段 |
| POST | `/user/del` | 删一个 |
| GET | `/user/export` | 导出全部 |
| POST | `/user/import` | 导入（同 uid 覆盖） |
| POST | `/user/clear` | 清空，必须带 `confirm:"yes"` |
| GET | `/persona` | 当前性格 + 三套定义 |
| POST | `/persona` | 切换（`{active:"poison"}`），下一条生效 |
| POST | `/persona/over` | 改口头禅/禁用词/示例库 |
| POST | `/persona/test` | 试说一句（不记进「刚说过」） |

自检：`node bridge.mjs --selftest` —— 现在会顺带验 uid 提取和档案计数。

## 七、踩到的坑

1. **`user.id` 被丢了**（见第三节）。这是记忆系统最大的前置问题。
2. **模型会把档案数字念出来** → user 行尾巴加「别说这些数字」。
3. **礼物走模型后漏点名** → 出口校验，没有昵称就退回本地模板。
4. **`startMedia` 重名**：这次改动期间文件被外部改过（礼物档位媒体加了一个
   `startMedia(item, meta)`），和音乐那个无参 `startMedia()` 撞了，桥直接起不来。
   已把音乐那个改名 `startMusic()`，三个调用点同步。**跟本需求无关，但必须记一笔** ——
   以后加函数前先 grep 一下名字。

## 八、验收对照（需求给的标准）

| # | 标准 | 状态 |
|---|---|---|
| 1 | 跨门槛换装 | ❌ 服装不做 |
| 2 | 重启后数据保留 | ✅ 实测 `--selftest` 写盘读回 |
| 3 | 不同用户文案不同 | ✅ 新人/老粉/榜一三种实测都不同 |
| 4 | 三性格风格不同 | ✅ 同一句「这歌真好听」三种口气 |
| 5 | DeepSeek 不可用回退示例库 | ✅ 模型挂了从当前性格的示例库抽（面板可改），抽不到才走通用话术 |
| 6 | 清空需二次确认 | ✅ 后端强制 |
| 7 | 展示区不遮挡 | ❌ 没动 |

第 5 条的补法（当天做完）：`localReply` 的兜底分支先调 `personaSamples()`，
有示例就 65% 概率从里面抽一句，抽不到才走通用话术。
实测断网时 —— 有梗说「啊这，你这波有点东西」，毒嘴说「你这个人……算了，还算有点良心」，
确实是两个人的嘴。
