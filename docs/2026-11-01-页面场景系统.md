# 页面场景系统（二选一：日常横屏 / 炒股竖屏）

2026-11-01 主人定下的规矩，原话：

> 我现在是二选一懂吗，启动炒股或者之前的页面，然后后端是公用的。
> 两个是不同一套的，每个人的人设也是不一样的，切换页面给 AI 的提示词也是不一样的。
> 每个页面有每个页面的组件，页面的组件还可以重复拿来使用，桥是一样的。

一句话：**一个页面 = 画面渲染器 + 人设卡 + 场景简报 + 素材 + 歌单；桥、音乐服务、素材库是共用的。**

## 一、配置在哪

`cache/scenes.json`：

```json
{
  "active": "stock",
  "list": [
    { "id": "live",  "name": "日常横屏", "render": "overlay", "persona": "dafeiyu-live",
      "scene": "live",  "media": "live" },
    { "id": "stock", "name": "炒股竖屏", "render": "stock",   "persona": "dafeiyu-live",
      "scene": "stock", "media": "stock" }
  ]
}
```

| 字段 | 干什么 |
|---|---|
| `render` | 起哪个画面进程：`overlay` = `native/overlay.py`（1920×1080 横屏），`stock` = `native/stock/run.py`（1080×1920 竖屏） |
| `persona` | 人设卡文件名（`prompts/<persona>.md`） |
| `scene` | 场景简报（`prompts/scene/<scene>.md`），拼进 system prompt |
| `media` | 素材属性页（留着的扩展点，暂时没用上） |

**要加第三个页面**：`list` 里加一条 + 写 `prompts/scene/<id>.md` + 决定 `render` 指哪个渲染器。
界面侧的入口在两处，都得同步加：
- `index.html` 的 `PAGES` / `NAV` / 侧栏「页面」下拉
- `README` 不写，看这份就够

## 二、切换（`server.mjs` 的 `sceneSwitch()`）

```
POST /scene  {id:"stock"}    切过去（同时保证那个画面进程活着）
GET  /scene                  当前是谁、都有哪些、画面进程在跑没
```

切换四步，顺序不能乱：

1. **停旧画面**（`stockStop()` / `overlayStop()`）—— 二选一，同一时刻只该有一个画面进程
2. **起新画面**（`stockStart()` / `overlayStart()`）
   ⚠️ `overlayStart()` 的默认值必须是 `o.withOverlay === true`。写成 `!== false` 的话
   「起桥」会顺手把横屏浮层也拉起来，台词就变成两套画面同时在跑（踩过）。
3. 写 `scenes.json` 的 `active`
4. 歌单联动（见下）

## 三、AI 那头的 prompt 怎么拼（`reply.mjs`）

`getSystem()` 四段拼接，顺序就是这个：

```js
[loadPersona(), skinBlock(), sceneBlock(), personaBlock()]
```

- 前两段（人设卡、皮套）**跨场景不变** → 切场景时前缀缓存照样命中
- 后两段（场景简报、性格）跟着场景走 → 只有它们失效

所以切页面不会把整条 prompt 缓存打掉。改这段拼接时记住这个顺序，别把
会变的段塞到前面去。

`prompts/scene/stock.md` 里有一条硬规矩，别删：

> 别人问「你在炒股吗」，直接认：「对啊，模拟盘，瞎玩」。**不许反问「什么炒股」**。

她自己开的盘，反问她「什么炒股」是灾难。这条是主人当场骂出来的。

## 四、歌单跟着页面走（2026-11-01 晚加）

存储：`cache/playlists.json`，`{"<页面id>": [曲目...]}`。
曲目只留 `{id, name, artists, durationMs, album}` —— 别把搜索结果整坨写进去。

接口在**音乐服务**（`:18083`），不在桥里 —— 播放器才是歌单的归属方：

```
GET  /playlist?name=stock              读某页歌单
GET  /playlist                         读全部
POST /playlist        {name, tracks}   覆盖某页歌单
POST /playlist/export {name}           把「正在放的 + 队列里排着的」存成某页歌单
POST /playlist/apply  {name, autoplay} 换成某页歌单
```

`sceneSwitch()` 里就两句，规矩只有两条：

- **切走时自动存**：`export` 旧页面 → 主人在这个页面点过哪些歌，切回来还是那些，不用手动保存
- **切来时只认有歌的**：`apply` 新页面，歌单是空的就**什么都不动**

  ⚠️ 绝不能因为「新页面还没配歌单」就把正在放的音乐清掉。

界面：设置 → 声音 → **按页面分歌单**。能选页面、看列表、删单首、清空、
粘贴歌名批量搜（一行一首，写「歌名」或「歌名 - 歌手」）。
批量加走 `/search` 拿第一条结果的 id —— **不让用户手填 id**，
没人记得住，抄错一位就是「找到是找到了但放不出来」。

## 五、容易踩的地方

- **音乐服务没起时切页面不能卡住**：`musicCall()` 3 秒超时，失败就返回
  `{ok:false}`，切页面的主流程不 await 它的成败。
- **两个渲染器都得认自己想看的状态**：竖屏只读 `/state.json` 里的在线/弹幕/白饭，
  横屏读得多一些。想让新页面用上新数据，先确认那个渲染器会读它。
- **端口**：对外只有 `:18082`（主控）。`:18084` 是竖屏进程的内部端口，
  走 `/stock/*` 反代，用户不用记第二个号。
