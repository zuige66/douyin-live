# 2026-10-30 开播 / 下播 一键工作流

把「开播」和「下播」各做成一步，**人双击也能用，agent 也能跑**。

## 一、为什么做

原来开播要三步（双击 start.cmd → 网页点开播 → 直播伴侣里再点），下播还要额外
记得去网页停桥、还可能「全停了还有音乐」。而且这两件事分属两套系统：

- **直播伴侣开播/关播** —— 只有 Mate 提权代理（`:18085`，UIA）能点；
- **桥 / 画面 / 音乐** —— 由 zhibo 主控 `server.mjs`（`:18082`）管。

`/ctl/all`（起全）和 `/ctl/stop`（停全）只覆盖第二套，第一套得另走 Mate。
所以需要一个把两套串起来的编排。

## 二、文件

| 文件 | 作用 |
|---|---|
| `tools/live.mjs` | 编排核心。`node tools/live.mjs <start|stop|status>` |
| `live-start.cmd` | 双击 = 开播。人双击会 pause 看结果；agent 用 `live-start.cmd --no-pause` |
| `live-stop.cmd` | 双击 = 下播（全关） |
| `live-status.cmd` | 双击 = 只看状态（只读，无副作用） |

`.cmd` 只是薄包装（找 node → 调 `tools/live.mjs`），**内容纯 ASCII**（cmd.exe 会把
UTF-8 中文的 echo/rem 当命令解析）；用 `chcp 65001` 让 node 输出的中文正常显示。

## 三、两个工作流各做什么

### 开播 `live.mjs start`
1. 确保 **Mate 提权代理**在（`/health`）；没起就明确报错让你开 `start-mate-agent.cmd`；
2. 确保 **主控 :18082** 在；没起就 `detached` 拉起 `server.mjs`（隐藏后台，父进程退也不影响）；
3. 若直播伴侣没开 → `/launch` 拉起；然后 Mate `live_start`（= 点「开始直播」）；
4. **等 6 秒**让房间在抖音侧变活跃；
5. `POST /ctl/all` → 起桥 + 画面 + 音乐（内部顺序：音乐 → 桥 → 浮层）；
6. 等桥从「待机」连上房间（最多 15s），打印状态。

> 🔴 **顺序铁律：先开播 → 再起桥。** `bridge.mjs` 的 `start_live_listen` 是「先返回
> success 再后台建连」；桥若在房间没活时先起，`LISTEN_OK` 被置真但 WS 没连上 ⇒ 监听
> **假活**，开播后 [live] 处理器再调会被去重跳过 ⇒ 永远 0 弹幕（「说话不理我」）。
> 详见 `docs/2026-10-29-直播伴侣MCP助手.md` 与本目录的启动顺序记录。
> （bridge 里另有看门狗:监听灯绿+房间在播+90s 零弹幕会自动硬重连，兜底。）

### 下播 `live.mjs stop`
1. Mate `live_stop`（= 点「关播」，自动点掉「确认要结束当前直播吗？」）；
   - 代理没起也能继续：只警告，照样停桥/音乐；
2. `POST /ctl/stop` → 停桥 + 画面 + **按停**音乐；
3. **彻底杀 musicd**：`/ctl/stop` 只是暂停、服务还在（「全停了还有音乐」的根源），
   所以这里再按端口 `:18083` 找到监听进程，确认是 `node.exe` 才 `taskkill /T /F`；
4. 打印状态。

## 四、用法

人（双击任意 `.cmd`，看结果后按任意键关闭）：

```
live-start.cmd      # 开播
live-stop.cmd       # 下播（全关）
live-status.cmd     # 查状态
```

agent / 命令行（加 `--no-pause` 不阻塞）：

```bat
live-start.cmd --no-pause
live-stop.cmd --no-pause
node tools/live.mjs start      :: 或直接跑核心
node tools/live.mjs stop
node tools/live.mjs status
```

退出码：`0` 成功 / `1` 失败（开播没成、主控起不来等）/ `2` 参数非法。

## 五、前置与边界

- **Mate 提权代理必须起着**（`:18085`）。它一般由计划任务 `zhibo-mate-agent` 在登录时
  自启；万一没起，双击 `start-mate-agent.cmd`（一次 UAC）即可。代理没起时
  `live-start/stop` 会明确报错，不会假装成功。
- 只点「开播 / 关播 / 确认」三个按钮，**不碰账号、实名、推流码**。
- `live-start` 在已经直播时是**幂等**的：检测到在播就跳过开播，只补 `/ctl/all`，
  不会打断正在进行的直播。
- 「彻底关音乐」会杀掉 `musicd` 进程；下次 `live-start`（或 `/ctl/all`）会自动把它拉回来。

## 六、为什么用 node 核心 + 薄 .cmd

- 令牌读取（`.run/mate-token`）、JSON、HTTP、顺序、重试、友好报错在 node 里都干净；
- **node 原生 fetch（undici）默认不走系统代理**，比 curl 稳 —— 用 curl 调本地端口时
  偶尔会被 `HTTP_PROXY` 干扰，返回一个假的「upstream connect failed」；
- `.cmd` 只负责「找 node → 转调」，人双击、agent 都能用，逻辑只维护一份。

## 七、踩过的点

1. **`taskkill /FI /PID` 在 Git Bash 里参数会被吞**（`/FI` 被当成路径）→ 所以杀进程
   统一在 node 里 `spawnSync('taskkill', [...])`，不走 shell 拼接。
2. **`.cmd` 末尾不能无条件 `pause`**，否则 agent 卡住 → 用「带 `--no-pause` 就不 pause」。
3. **`cache/mate.json` 可能不存在** → 一律回落 `127.0.0.1:18085`（和 mate-mcp.mjs 一致）。
4. **换机器 / 重启后主控常没起**（`start.cmd` 是手动双击的）→ `live-start` 会自动拉起。
5. 2026-10-30 晚实测：Mate 提权代理会随会话/时间掉（`:18085` 不监听），但直播伴侣
   本身照常在推流 —— 只是「开播/下播」控制不了。工作流据此给了明确提示。
6. **`.cmd` 的 rem/echo 必须纯 ASCII**（2026-10-31）。第一版在 `rem` 里写了中文
   「直播伴侣 开播/关播」，cmd.exe 把片段当命令执行，stderr 全是
   `'-stop.cmd' 不是内部或外部命令` / `'Mate' ...` 之类乱码报错（虽然不影响执行）。
   已把三个 `.cmd` 全部改成纯英文注释。**改 `.cmd` 后务必验证非 ASCII 行数为 0。**
7. **直播伴侣 UI 改版（2026-10-31 实测）**：关播按钮不再固定叫「MM:SS 关播」，同一时刻
   树里可能还有一个干扰项「下播」。`mate_uia.py` 的严格守卫只认「时长+关播」，遇到只
   读到「下播」的刹那会拒绝（报「没找到带直播时长的关播按钮，判断为当前未开播」）。
   手动兜底（已验证可用）：`mate_click name="关播" exact=false` 点真按钮 →
   `mate_click name="确认" exact=true` 点确认 → 状态变「未开播」。
   ✅ **已加自动兜底**（主人 2026-10-31 拍板）：`live.mjs stop()` 先走 `/live/stop`，
   失败则调 `fallbackStop()` —— 模糊点「关播」（退而精确点「下播」）→ 精确点「确认」
   （重试，绕开失效副本）→ 读 `/state` 复核。⚠️ 兜底会绕过严格守卫，
   但**仅在正规 `/live/stop` 已经失败后**才触发，且用户确实是要求下播的语境。
8. **killMusic 幂等**（2026-10-31）：端口没监听 + `pids.json` 里是过期 `musicPid` 时，
   `procName` 返回空应判定「本来就没在跑」，不能拿过期 pid 去 `taskkill`（否则报
   「没找到进程」。已修。}
